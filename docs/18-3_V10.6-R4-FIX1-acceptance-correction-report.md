# V10.6-R4-FIX1 验收修正执行报告

> 任务编号：V10.6-R4-FIX1-ACCEPTANCE-CORRECTION
> 前置版本：V10.6-R4-ISSUE-CLOSED-LOOP
> 禁止操作：未部署、未提交、未推送；未进入 R5

## 1. 幂等唯一范围

- 幂等作用域改为 `realm + project + work_item + client_key` 确定性组合。
- 冲突回退使用完全相同的 Realm/Project/Task 条件。
- 两个 Realm 使用相同幂等键不会互返或互覆盖，已通过双会话/双 Realm 测试。

## 2. 验证权限与 truth scope

- 通用 PATCH 禁止写入 `verified`，只能通过专用验证接口完成。
- `node_editor` 直接 PATCH `verified` 返回 400。
- 问题录入只允许 `observed`；分类建议与 Skill 草稿固定为 `inferred`。
- 客户端写入 `verified` 一律拒绝。

## 3. 分类审核闭环

- `classify` 必须提交 `expected_version`。
- `verified/cancelled` 终态问题禁止重新分类。
- 域主可编辑 category、severity、impact、urgency、负责人。
- 分类确认后 `classification_status=confirmed`，并追加事件。

## 4. Skill 闭环

- verified 状态显示生成 Skill 按钮。
- Skill 内容引用 final_solution、成功/部分成功尝试、工具、证据和适用边界。
- Skill 草稿支持详情与编辑，修改必须提交版本。
- 域主确认前保持 `draft`、`owner_confirmed=false`、`truth_scope=inferred`。
- Skill 查询在 SQL 层限定 Realm/Project；多问题生成必须同项目；空 issue_ids 返回 400。

## 5. 前端

- 任务卡片显示关联问题数量和“查看问题”入口。
- 问题录入使用正式弹窗，不再使用 window.prompt。
- 补齐分类审核、负责人、严重度、影响、处理结果、工具、失败原因和证据输入。
- execution 导航状态改为 open。
- 按钮按后端 `can_*` 权限真实禁用。
