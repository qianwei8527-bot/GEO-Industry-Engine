# V10.6-R4-FIX2 最终收口执行报告

> 前置版本：V10.6-R4-FIX1-ACCEPTANCE-CORRECTION

## 1. 创建问题与 truth scope

- 服务端创建问题时固定 `truth_scope="observed"`，客户端传入其他值返回 400。
- 新增 API 级测试 `test_api_create_rejects_verified_truth_scope`，断言响应 400 且提示 `observed`。
- 通用 PATCH 继续禁止写入 `verified`，truth_scope 白名单只允许 `observed`。

## 2. 幂等作用域

- 幂等作用域改为规范化字符串 `realm:project:work_item:client_key` 的完整 SHA-256，数据库存储固定 64 字符哈希。
- 冲突回退使用完全相同的 Realm/Project/Task 条件，跨 Realm 同键不互返、不覆盖。
- 新增 `test_idempotency_hash_fixed_length`，使用真实 Realm、Project、plan_task 和客户端时间键验证长度。
- 问题 DTO 返回 `idempotency_key`（SHA-256 哈希，非原始密钥），E2E 断言长度为 64。

## 3. Skill 按钮与真实闭环

- “生成 Skill 草稿”按钮已移出 `can_update_issue` 容器，使用 `canShowSkillButton(status, can_generate_skill)`，verified 终态可真实显示。
- 浏览器 E2E 在真实路由上点击按钮，等待“Skill 草稿已生成”后继续编辑、保存、确认。
- 确认后的 Skill 不再显示编辑控件；终态问题不再暴露 triaged 等写操作。

## 4. Skill 顶层真实性

- `ProjectArtifact.truth_status` 固定为 `inferred`，与 `content_json.truth_scope`、`metadata_json.truth_scope` 保持一致。
- 测试断言三层字段均为 `inferred`。

## 5. Skill 编辑边界

- 只允许白名单业务字段：name、适用场景、触发条件、前置条件、inputs、steps、tools、expected_output、验证标准、common_failures、prohibited_usage 等。
- `source_issues`、`source_attempts`、`provenance`、`truth_scope`、`owner_confirmed`、`version`、`source_hash` 禁止客户端覆盖。
- 仅 `draft` 可编辑，使用行锁 `with_for_update` 与 `expected_version`。
- 编辑后强制 `owner_confirmed=false`、`truth_scope=inferred`，避免 confirmed/owner_confirmed 矛盾。
- 新增双数据库会话并发测试，同版本并发编辑只有一个成功。

## 6. Skill 内容生成

- success/partial 尝试进入推荐步骤和工具；failed 尝试进入 common_failures。
- 修正嵌套 `attempt.tool` 读取，工具不再因层级错误而始终为空。
- `final_solution` 写入 expected_output，`applicability_boundary` 写入 prohibited_usage。
- 测试断言工具集合、成功步骤、失败原因和最终方案均真实进入草稿。

## 7. 分类审核闭环

- verified/cancelled 终态禁止重新分类和分类确认。
- 分类确认仅域主或 `node_reviewer`；普通 `node_editor` 拒绝。
- category 为空时确认返回 400。
- 分类字段修改后自动回到 `suggested`，并追加 `classification_reopened`、`category_updated` 事件。

## 8. 前端补齐

- 补齐 final_solution、适用边界、action、开始/结束时间输入。
- 负责人改为 Realm 成员下拉，不再手填 user UUID；后端同时校验 Realm 成员身份。
- Skill 详情展示结构化草稿和可编辑字段。
