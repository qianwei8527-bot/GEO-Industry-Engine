| Next.js | 14 (App Router) | pnpm |
| SQLAlchemy | 2.0+ | Poetry |

### 1.2 本地开发启动

```bash
# 1. 启动基础设施
docker-compose up -d postgres redis

# 2. 初始化数据库
cd backend && poetry run alembic upgrade head

# 3. 启动后端 (端口8000)
poetry run uvicorn app.main:app --reload

# 4. 启动前端 (端口3000)
cd frontend && pnpm dev
```

## 二、版本管理策略

### 2.1 Git分支策略

```
main           <- 生产就绪代码，保护分支
  |
  +-- codex/*  <- 功能分支 (codex/sprint-5-frontend)
  |
  +-- hotfix/* <- 紧急修复
```

分支命名: codex/{sprint}-{feature} 或遵循用户指定的前缀

### 2.2 提交规范

```
type(scope): description

类型: feat/fix/docs/refactor/test/chore/config
范围: backend/frontend/config/docs/agents
示例: feat(backend): add YAML config loader for Decision Engine
```

### 2.3 发布流程

1. 功能分支 -> PR -> Code Review
2. CI全部通过 -> merge到main
3. Tag版本号 (遵循用户指定)
4. CI自动构建制品
5. 部署staging验证
6. 手动审批部署production

## 四、运维手册

### 4.1 日常运维

| 任务 | 频率 | 负责人 |
|------|------|--------|
| 数据库备份验证 | 每日 | 自动化 |
| 日志检查/异常排查 | 每日 | 运维 |
| 证书更新检查 | 每周 | 自动化 |
| 依赖安全扫描 | 每周 | CI自动 (Dependabot) |
| 性能基线检查 | 每月 | 运维 |
| 灾难恢复演练 | 每季 | 运维 |

### 4.2 常见问题处理

| 问题 | 排查步骤 |
|------|---------|
| API响应慢 | 检查DB慢查询 -> 检查Redis命中率 -> 检查Decision Engine重算 |
| 评分不更新 | 检查Event管道 -> 检查ConfigLoader -> 检查计算任务队列 |
| Agent无响应 | 检查Agent进程 -> 检查Tool调用超时 -> 检查IntentRouter |
