## 一、数据治理框架

### 1.1 数据分类分级

| 分类 | 级别 | 内容 | 保护措施 |
|------|:--:|------|---------|
| 公开数据 | L0 | 企业公开信息、行业指数、排行榜 | 无限制 |
| 内部数据 | L1 | 聚合统计、脱敏分析结果 | 认证后可访问 |
| 敏感数据 | L2 | 企业详细数据、API配额信息 | RBAC + 审批 |
| 机密数据 | L3 | 个人身份信息、财务数据 | 加密 + 审计 + 最小权限 |

### 1.2 数据质量五维模型

| 维度 | 定义 | 评分方式 | 关联 |
|------|------|---------|------|
| 完整度 (Completeness) | 必填字段填充率 | 已填/应填 * 100 | Entity.quality_score |
| 准确度 (Accuracy) | 数据与事实的一致性 | 交叉验证通过率 | 认证审核 |
| 时效性 (Timeliness) | 数据的新鲜程度 | 距最后更新时间 | Event时间轴 |
| 可信度 (Trustworthiness) | 来源可靠度 | source_level权重 | Trust Score |
| 一致性 (Consistency) | 跨系统/平台的统一性 | name_consistency | Entity质量 |

### 1.3 数据来源等级

| 等级 | 来源类型 | 权重 | 示例 |
|:----:|---------|:---:|------|
| A | 官方/政府/权威机构 | 1.0 | 营业执照/政府备案/ISO认证 |
| B | 第三方验证平台 | 0.8 | 天眼查/企查查/第三方审计 |
| C | 行业媒体/社区认可 | 0.5 | 行业媒体报道/社区贡献 |
| D | 自主申报 | 0.3 | 企业自填信息 |

### 1.4 数据生命周期

创建 -> 验证 -> 使用 -> 更新 -> 归档/删除

每阶段触发条件: 创建(用户注册/数据导入) -> 验证(AI自动+人工) -> 使用(API/前端消费) -> 更新(事件触发/定期刷新) -> 归档(过期/无效数据)

## 二、国际化设计

### 2.1 多语言

| 层面 | 实现方式 | 优先级 |
|------|---------|:--:|
| 前端UI | next-intl / i18next | P1 |
| 后端错误消息 | gettext / babel | P1 |
| 产业分类标签 | 数据库多语言字段 | P2 |
| 评分解释生成 | LLM多语言输出 | P2 |
| 认证证书 | 模板多语言 | P2 |

### 2.2 区域化 (Localization)

- 日期格式: 根据locale自动切换
- 数字格式: 千分位/小数点
- 货币: 自动换算+显示
- 时区: 用户设置时区

### 2.3 多语言路由

```
/zh-CN/detection  -> 中文界面
/en/detection     -> 英文界面
/ja/detection     -> 日文界面
```

默认: 浏览器 Accept-Language header

## 三、品牌体系设计

### 3.1 品牌命名体系

| 层级 | 名称 | 说明 |
|------|------|------|
| 主品牌 | GEO-Industry-Engine | 产业生态操作系统 |
| 产品名 | GEO产业引擎 | 中文对外名称 |
| 子系统 | 检测中心/认证中心/产业导航/数据资产/交易市场 | 五大入口 |
| 技术组件 | Context Engine / Decision Engine / Agent OS | 内部名称 |

### 3.2 视觉标识

- 主色系: 行业技术色(深蓝#1a365d / 科技蓝#2b6cb0)
- 辅助色: 五大系统各一色 (检测=绿/认证=金/导航=蓝/资产=紫/交易=橙)
- 认证标识: L0灰/L1蓝标/L2金标/L3紫标/L4红钻
- 图标库: Lucide Icons (统一)

### 3.3 品牌语调 (Tone of Voice)

- 专业但不冰冷: 使用行业术语但解释清晰
- 赋能而非说教: 强调用户能获得什么
- 生态而非工具: 多用连接/位置/生态类词汇
