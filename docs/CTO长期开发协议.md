# 恒域世界（GEO-Industry-Engine）长期工程开发协议 v4.0

> 最后更新：2026-08-11 | 状态：stable | 替代：v3.2（GEO Universe 六层架构）
> 上位依据：恒域世界 V10.6

## 零、最高指令

任何开发任务必须回答三个问题：

1. 服务哪个真实域主的哪个经营任务？
2. 处于单域经营闭环的哪一步（资料→分析→确认→计划→执行→问题→结果→复盘→资产）？
3. 产生什么可验证结果（证据、结果、复用能力）？

三个问题不能全部回答的，不开发。

## 一、最高原则（保留工程纪律）

1. 事实优先线：代码 > 测试 > API > 配置 > 文档 > 历史报告。
2. 核心模型测试覆盖率 >= 80%；API 契约测试覆盖所有端点。
3. YAML 配置必须被代码实际读取，否则删除。
4. 所有执行链必须可追踪：输入、输出、Provider/模型版本、配置哈希、引用、成本、权限、状态。
5. AI 与工具不得制造 verified 事实；未知标 unknown，不补造。

## 二、禁止事项（V10.6）

1. 未经任务授权横向铺开模型、行业或页面。
2. 建立平行 Task / Evidence / Outcome / Reputation / Realm 体系。
3. 域主或 AI 自行制造 verified；Outcome 直接改 Reputation。
4. 把 Codex/OpenClaw/Dify/n8n 塞入核心运行时或作为业务真相源。
5. 把模拟、演示、测试数据冒充真实数据。
6. 未批准新增数据库模型和迁移。
7. 未经用户明确授权提交、推送、部署或发布。

## 三、命名规范（V10.6）

| 中文 | 英文/代码 | 说明 |
|------|----------|------|
| 恒域世界 | 产品名 | 上位产品 |
| 域 | Realm | 基本经营单元 |
| 应用面 | Application Surface | 不再使用"前端"作为产品形态词 |
| 统一壳层 | AppShell | 四应用面共用 |
| 域主工作台 | Owner Workbench | 主产品 |
| 兼容层 | Node / Entity | 现有代码兼容实现，不破坏性重命名 |

## 四、架构固定结构

- 4 个应用面
- 10 个中台能力域
- 3 个技术底座
- 6 种页面模板
- 6 种模块状态
- 5 级 truth scope

详见 17-2 细节设计。
