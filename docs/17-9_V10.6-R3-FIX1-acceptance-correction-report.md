## 1. 工作流来源修正

- 平台 `platform_seed` 只提供空白工作流结构、字段规范和校验能力，不再内置行业执行流程。
- 仓库既有 GEO 起步流程改为 `realm_template`，并记录 `realm_id`、`owner_id`、`source_version`、`source_hash`、`owner_confirmed`、`provenance`。
- `owner_defined` 已通过真实 UI 提供 JSON 模板提交能力；未实现前不会出现不可用选项。
- 后端严格校验 `source_type`、`source_id` 与 Realm 归属，非法来源直接拒绝。

## 2. 计划任务隔离与 task_version

- R3 查询、幂等检查、更新、完成判断、提醒和 CSV 全部限定 `work_type=plan_task` 与当前 `project_id`。
- `acceptance_criteria`、`required_materials`、`purpose`、`risks` 等写入现有原生字段。
- 每个正式任务在 `metadata_json` 保存可复用 `task_version`，修改必须提交 `expected_task_version`。
- 任务负责人必须是当前 Realm 有效成员，否则确认整体回滚。

## 3. 状态与并发

严格状态机：

```text
planned → in_progress
in_progress → blocked/completed
blocked → in_progress
completed 为终态
```

- `plan_completed` 为终态，禁止回退或继续修改。
- 拒绝零任务确认、非法日期、跨 Realm 依赖和无效负责人。
- 同版本并发修改只有一个成功；并发确认只保留一套任务。
- 确认失败整体回滚，不残留任务或确认快照。

## 4. 真实 UI

- 后端 `list_plan` 返回 `can_edit`、`can_confirm`、`can_update_task`。
- 只有域主显示确认操作；只读用户的全部写控件禁用。
- 补齐任务全部字段：目的、说明、预期产出、验收标准、所需材料、负责人、提醒、风险、执行模式、排序和依赖。
- loading / empty / partial / blocked / error / no-permission / normal 正确区分。
- `v106-all-pages-design-preview.html` 已同步更新 FIX1 元数据与场景。
