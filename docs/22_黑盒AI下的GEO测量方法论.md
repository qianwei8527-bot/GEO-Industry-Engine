# 黑盒AI下的GEO测量方法论

> AI模型是黑盒。我们不声称"理解AI如何推荐"。我们只测量"AI实际推荐了什么"。

---

## 一、核心承认

### 1.1 我们无法控制的

| 不可控因素 | 影响 | 应对方式 |
|-----------|------|---------|
| 模型闭源 | 无法查看推荐逻辑 | 只观察输出，不推演内部 |
| 推荐逻辑黑盒 | 不知道A比B重要的原因 | 统计规律代替因果解释 |
| 结果随机性 | 同Prompt不同结果 | 重复测量+置信区间 |
| 模型更新 | 行为突然变化 | 持续监测+变更告警 |
| Prompt敏感 | 措辞不同结果不同 | 标准化Prompt库 |

### 1.2 我们能测量的

| 可测量项 | 测量方式 | 可靠性 |
|---------|---------|--------|
| 特定Prompt下推荐了哪些企业 | 控制变量重复测量 | 高 |
| 企业排名随时间的变化趋势 | 时间序列采样 | 中-高 |
| 不同模型间的推荐差异 | 跨模型对比 | 中 |
| 内容变更前后的推荐变化 | A/B测试 | 高（实验设计控制） |
| 引用来源分布 | 分析回答中的引用 | 中-高 |

### 1.3 GEO评分的真实含义

**GEO评分不是"AI对这个品牌的评价"，而是"在控制变量条件下，我们观察到这个品牌被AI推荐的频率和方式"。**

这是一个统计学测量，而不是一个心理学评估。

---

## 二、测量协议

### 2.1 控制变量法

为了减少随机性的影响，每次测量遵循严格协议：

```
固定Prompt库（100个行业标准查询）
    ↓
固定时间窗口（每天UTC 10:00-12:00）
    ↓
固定模型版本（记录模型版本号）
    ↓
重复测量（每个Prompt x 3次）
    ↓
环境控制（同一IP、同一网络、同一参数）
    ↓
记录原始数据 + 置信区间
```

### 2.2 标准化Prompt库

每个行业维护一组标准化Prompt，确保跨时间可比：

| 行业 | Prompt示例 | 来源 |
|------|-----------|------|
| 制造 | "国内工业机器人供应商推荐" | 行业标准问题 |
| 企业服务 | "最适合制造业的ERP系统" | 用户调研提炼 |
| 医疗 | "中国基因治疗领域领先企业" | 行业常见问题 |
| 投资 | "新能源汽车板块值得关注的企业" | 投资者典型问题 |

Prompt库每季度审核更新，保证与真实用户问题一致。

### 2.3 重复测量与聚合

```
单次测量值 M1, M2, M3
    ↓
计算中位数 M_median（抗异常值）
    ↓
计算置信区间 CI_95
    ↓
与上次测量对比 Δ
    ↓
Δ > CI → 真实变化
Δ <= CI → 噪音
```

## 三、评分可靠性

### 3.1 置信度等级

GEO评分不再是一个"精确数字"，而是"范围+置信度"：

| 置信度 | 条件 | 用户看到 | 建议行为 |
|--------|------|---------|---------|
| 高 | 连续7天+结果一致+多模型一致 | "89分" | 可作为决策依据 |
| 中 | 连续3天+部分模型一致 | "78分 ± 5" | 参考，建议持续监测 |
| 低 | 单次测量+模型间差异大 | "65分 ± 15" | 趋势参考，不可作为决策依据 |
| 极低 | 仅1次测量 | "暂无可靠数据" | 先积累数据 |

### 3.2 置信度计算公式

```
Confidence =
  measurement_count_coverage × 0.35
+ model_consistency × 0.30
+ temporal_stability × 0.20
+ prompt_robustness × 0.15

其中：
  measurement_count_coverage: 测量次数/标准次数
  model_consistency: 多模型结果一致度
  temporal_stability: 连续时间的波动幅度
  prompt_robustness: 类似Prompt的结果一致度
```

### 3.3 用户界面原则

| 场景 | 前端的表达方式 |
|------|-------------|
| 高置信度 | 显示单一数字 + "稳定"标签 |
| 中置信度 | 显示范围 + "正常波动"标签 |
| 低置信度 | 显示趋势线 + "数据积累中"提示 |
| 变化显著 | 显示变化箭头 + "较上周+5" |
| 变化不显著 | 不显示变化（避免误导） |

## 四、实验替代解释

当无法解释"为什么AI推荐A不推荐B"时，用实验来回答"我们做了什么改变了结果"。

### 4.1 实验是唯一的因果证据

在AI黑盒环境下，实验是唯一能建立因果关系的工具：

```
不能问：为什么AI推荐上升了？
能问：我们增加了案例页面后，推荐率从12%升到18%，变化显著（p<0.05）
```

### 4.2 实验设计

| 实验类型 | 操作 | 测量 | 周期 |
|---------|------|------|------|
| 内容实验 | 新增/修改特定内容 | 该内容的AI引用率变化 | 1-4周 |
| 来源实验 | 在权威来源增加信息 | 品牌在AI回答中的出现率 | 2-8周 |
| 认证实验 | 完成平台认证 | 信任评分变化 | 即时-2周 |
| 多维组合 | 组合以上多项措施 | 综合GEO评分变化 | 4-12周 |

### 4.3 实验结果判定

```
结果变化量 > 置信区间 × 2 → 有效实验
结果变化量 > 置信区间 × 1 → 趋势性发现
结果变化量 <= 置信区间 → 无效（继续）
```

## 五、透明化原则

### 5.1 对用户透明

所有评分附带元数据：

```
GEO评分: 78分
置信度: 中（基于12次测量，7天数据）
数据来源: ChatGPT x 4次, Gemini x 4次, Claude x 4次
测量时间: 2026-07-25 ~ 2026-07-31
变化趋势: 较上周+3分（稳定上升）
```

### 5.2 不承诺无法验证的事

| 承诺 | 状态 |
|------|------|
| "我们帮你提升AI推荐率" | ✅ 可验证（实验）|
| "你的AI可见度会提升" | ✅ 可验证（测量）|
| "AI会更喜欢你的品牌" | ❌ 无法验证 |
| "你的GEO评分一定会上升" | ❌ 取决于执行 |
| "我们知道AI为什么推荐谁" | ❌ 黑盒不可知 |

### 5.3 面对不确定性

当测量结果不确定时，坦诚告知用户：

```
"当前数据还不足以给出可靠判断。
建议：再积累3天数据，或调整优化策略后重测。"
```

比给出一个"虚假精确"的分数要好。

## 六、对产品架构的影响

| 受影响模块 | 具体影响 |
|-----------|---------|
| GEO评分算法 | 输出从单一分数改为"分数+置信度+趋势" |
| 增长实验 | 从辅助功能升级为核心功能（唯一因果证据来源）|
| 用户报告 | 必须包含置信度和数据来源说明 |
| Scanner Agent | 标准化测量协议 > 随意查询 |
| AI模型智能库 | 模型行为和结果随机性本身是需要追踪的数据 |
