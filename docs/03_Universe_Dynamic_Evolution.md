# Universe Dynamic Evolution（动态演化）

> V5 解决了空间结构（Universe 长什么样）。V6 解决时间维度（Universe 如何持续演化）。

---

## 第零章：从静态数据库到动态产业宇宙

当前状态：
- 节点是属性集合（Company 有 name, geo_score, industry_id）
- 关系是静态连线（A 和 B 是 competitor）
- 评分是快照（今天计算，存入数据库，直到下次手动更新）

目标状态：
- 节点有生命周期（诞生 -> 成长 -> 成熟 -> 衰退/转型 -> 消失）
- 关系随时间演化（今天竞争、明天合作、后天生态关键节点）
- 评分是动态流（每天自动更新，反映最新状态）
- 整个 Universe 像生物一样生长，被 AI 持续观察和驱动

---

## 第一章：Dynamic Graph（动态图）

### 1.1 不是 A -> B，而是时间序列

静态图：A 和 B 是竞争对手。永远如此。

动态图：
```
T0（2024-01）：A 成立，独立节点
T1（2024-06）：B 成立，A 和 B 进入竞争关系
T2（2025-03）：C 服务商同时服务 A 和 B，成为生态连接点
T3（2025-09）：A 和 B 在某个项目上合作，关系从竞争变为竞争+合作
T4（2026-01）：D 成立，A 和 B 的竞争关系减弱，D 成为主要威胁
```

### 1.2 实现要素

- **时间戳**：每条关系都有 created_at 和 valid_until
- **事件驱动**：GeoEvent 触发关系创建、修改、失效
- **历史回放**：可以查看任何历史时间点的关系网络
- **演化预测**：基于历史模式，预测未来可能的关系变化

### 1.3 每日刷新机制

AI Observation Agent 每天自动运行：
1. 扫描所有产业的公开信息变化
2. 检测新的企业、产品、能力出现
3. 检测现有关系的增强、减弱、消失
4. 生成 GeoEvent 记录
5. 触发地图局部或全局刷新

## 第二章：Node Evolution（节点演化）

### 2.1 每个节点都是生命

节点的生命周期阶段：

| 阶段 | 标志 | 系统行为 |
|------|------|---------|
| 诞生 | 新节点被创建（手工或 AI 发现） | 初始化 Position，标记为 New |
| 成长期 | GEO Score 上升，关系增加，证据累积 | Growth 建议高优先级推送 |
| 成熟期 | Score 稳定，关系达到峰值 | Connection 机会推荐 |
| 衰退期 | Score 下降，关系减弱，证据过期 | 风险预警，复苏建议 |
| 消失 | 无活动超过阈值 | 标记为 Inactive，保留历史数据 |

### 2.2 演化驱动因素

- **内部事件**：新产品发布、融资、认证、团队变化
- **外部事件**：赛道热度变化、政策变化、技术突破
- **关系事件**：新合作、竞争关系变化、生态角色变化

### 2.3 节点快照 vs 节点流

当前系统：Company 表存的是当前属性（快照）。

动态系统：每次属性变化产生一条 NodeSnapshot 记录：

- snapshot_id, node_id, timestamp, geo_score, trust_score, stage, evidence_count, relationship_count

这样就可以回答：
- 这个企业过去 12 个月的成长曲线是什么？
- 它的 GEO Score 在哪个月变化最大？为什么？
- 它的生命周期阶段转换是否符合行业规律？

## 第三章：AI Observation（AI 观察层）

### 3.1 不是 Agent 分析企业，是 Agent 分析产业

当前 Agent 职责：用户输入企业 -> Agent 分析 -> 返回报告。这是被动的。

AI Observation 的职责：系统主动、持续、全量扫描产业变化。

### 3.2 Observation Agent 工作流

```
每日自动触发：
    ↓
扫描外部信息源（公开数据、新闻、行业报告、AI 摘要）
    ↓
检测变化：
  - 新企业出现？
  - 新赛道形成？
  - 新能力需求？
  - 关系变化？
  - 评分需要更新？
    ↓
生成 ObservationRecord
    ↓
评估影响：
  - 触发哪些节点的演化？
  - 触发哪些地图的刷新？
    ↓
自动执行更新（需人工确认重大变化）
    ↓
生成 Observation Report（给系统管理员）
```

### 3.3 速度约束

- 每日至少扫描一次
- 重大事件（如新赛道形成）实时推送
- 非关键变化批量处理（每小时汇总一次）

## 第四章：Reputation Layer（信誉层）

### 4.1 信誉的定义

信誉不是评分。评分是快照。信誉是时间深度。

- 一个企业 GEO Score 85 = 当前表现好
- 一个企业 5 年连续信誉记录 + 持续上升趋势 = 长期可信

### 4.2 信誉的维度

| 维度 | 数据来源 | 权重 |
|------|---------|------|
| 交付记录 | 交易完成 + 评价 | 40% |
| 认证背书 | 第三方认证 + 行业背书 | 25% |
| 同行评价 | 产业内其他节点的评价 | 20% |
| AI 引用 | 被 AI 推荐的频率和质量 | 15% |

### 4.3 信誉的时间衰减

- 近 12 个月内的证据：权重 100%
- 12-24 个月：权重 70%
- 24-36 个月：权重 40%
- 36 个月以上：权重 20%（保留历史但不影响当前评分）

这保证：去年做得好不等于今天可信。持续交付才值得信赖。

## 第五章：演化触发的系统行为

| 触发事件 | 影响的层次 | 系统行为 |
|---------|-----------|---------|
| 新节点出现 | Node | 初始化 Position，标记为 New |
| Score 显著变化 | Node + Graph | 更新节点，刷新竞争关系 |
| 新关系建立 | Graph | 重新计算节点中心度，刷新地图 |
| 新赛道形成 | Graph + Evolution | 自动创建 Industry/Track，关联现有节点 |
| 信誉认证 | Reputation | 更新信誉分数，推送信用变化通知 |
| 时间衰减 | Reputation | 自动降权旧证据，触发企业关注 |
