# GEO测量方法论

> AI推荐系统是封闭的随机过程。GEO测量的任务不是解释它，而是以可控误差估计它。

---

## Module A: 认识论基础

### A.1 测量对象定义

GEO测量的对象不是"AI的真实想法"——那不存在。测量对象是：

**"在受控条件下，向指定AI系统提交标准化查询后，该系统输出文本中提及特定实体的频率、位置和语境。"**

简称：**AI可观测推荐行为（Observed AI Recommendation Behavior, OARB）**。

### A.2 可观测与不可观测的边界

| 可观测 | 不可观测 |
|--------|---------|
| 特定查询下的输出文本 | 模型的内部表征 |
| 输出文本中的实体提及 | 模型的推理路径 |
| 实体提及的时间序列变化 | 模型的更新日志 |
| 跨模型的输出差异 | 模型的训练数据构成 |
| 受控实验前后的输出变化 | 模型对特定实体的"真实看法" |

**边界法则**：GEO评分只描述可观测范围内的统计规律。任何超出此范围的解释都是推测，不应作为产品宣称。

### A.3 测量误差来源

| 误差类型 | 来源 | 性质 | 控制策略 |
|---------|------|------|---------|
| 采样误差 | 有限次测量 | 随机 | 增大样本量，报告置信区间 |
| 语境漂移 | 模型版本更新 | 系统 | 版本锁定，变更检测 |
| Prompt敏感度 | 措辞差异导致输出差异 | 随机+系统 | 标准化Prompt库，多Prompt交叉验证 |
| 时间效应 | 不同时间段模型行为不同 | 系统 | 固定时间窗口，同期群分析 |
| 测量干扰 | 测量行为本身影响结果 | 低（只读查询） | 无需特别处理 |

## Module B: 观测协议

### B.1 协议规范

每次观测必须遵循统一协议：

```
[观测指令]
Query Pool: Q_standard = {q_1, ..., q_100}   # 标准化查询集
Model Set: M = {m_1, ..., m_n}               # 目标模型
Time Window: T = [t0, t1] daily              # 每日固定时段
Replication: r = 3                            # 每查询每模型重复次数
Environment: E = {IP, params, version}        # 环境固定

[观测过程]
for each m in M:
    for each q in Q_standard:
        for rep in 1..r:
            record = query(m, q, E)
            store(record)
```

### B.2 标准化查询集

Q_standard 的维护规则：
- 每个行业至少10个查询
- 每季度审核更新（新增/淘汰/修正）
- 变更记录可追溯
- 版本号管理：Q_standard_v2026Q3

### B.3 原始记录格式

每条观测记录包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| observation_id | UUID | 唯一标识 |
| model_id | UUID | 目标模型 |
| query_id | UUID | 使用的标准化查询 |
| query_text | String | 实际发送的查询文本 |
| response_text | Text | 模型输出的完整文本 |
| response_time_ms | Int | 响应时间 |
| model_version | String | 模型版本标识 |
| environment_fingerprint | String | 环境指纹 |
| observed_at | DateTime | 观测时间戳 |
| raw_metadata | JSON | 额外的环境元数据 |

## Module C: 统计测量引擎

### C.1 核心指标体系

| 指标 | 符号 | 定义 | 估计方法 |
|------|------|------|---------|
| 可见度 | VR_b | P(品牌b出现在回答中 \| query, model) | Beta-Binomial |
| 排名 | RP_b | E[排名位置 \| 品牌b被提及] | Bootstrap均值 |
| 情感 | SS_b | E[情感得分 \| 品牌b被提及] | Bootstrap均值 |
| 引用深度 | CD_b | E[引用数量 \| 品牌b被提及] | Bootstrap均值 |
| 声量占比 | SoV_b | VR_b / Sum(VR_i) | Delta方法 |

### C.2 可见度估计（VR）

采用 Beta-Binomial 模型：

```
观测数据: k_b = 品牌b被提及的次数(共n次查询)
似然: k_b ~ Binomial(n, p_b)
先验: p_b ~ Beta(alpha=1, beta=1)  # 均匀无信息先验
后验: p_b | data ~ Beta(1+k_b, 1+n-k_b)

点估计: p_hat_b = (1+k_b) / (2+n)
置信区间: Beta分布的分位数(alpha=0.05)
```

**输出**: VR = (p_hat_b, CI_95_lower, CI_95_upper, n)

当n < 30时，置信区间宽度将较大，系统标记为"低置信度"。

### C.3 综合评分

GEO评分 = 加权聚合各指标：

```
GEO_Score = w1 * f(VR) + w2 * f(RP) + w3 * f(SS) + w4 * f(CD) + w5 * f(SoV)
```

其中 f() 是各指标的标准化函数（将原始值映射到0-100）。

权重的确定：
- Phase 1: 领域专家设定的固定权重（当前）
- Phase 2: 基于实验数据校准（需要积累100+实验）
- Phase 3: 模型自主学习最优权重（需要充足数据）

### C.4 趋势检测

采用简单移动平均 + 统计检验：

```
MA_t = mean(score_{t-6}, ..., score_t)  # 7日移动平均
delta = MA_t - MA_{t-7}                  # 周环比变化

如果 delta > 2 * sigma_noise → "显著上升"
如果 delta < -2 * sigma_noise → "显著下降"
否则 → "稳定"
```

sigma_noise 从历史数据中估计（取过去30天变化的标准差）。

### C.5 跨模型聚合

不同模型的结果通过加权平均聚合：

```
Aggregated_Score = sum(w_m * Score_m) / sum(w_m)

权重 w_m 基于：
- 该模型的用户规模估计（来自 ai_model_metrics）
- 该模型的历史测量稳定性（来自 ModelBehaviorPattern）
- 该模型与目标行业的相关度（来自 ai_model_industry_scores）
```

## Module D: 因果关系框架

### D.1 核心约束

在AI黑盒环境下，**单次观测无法建立因果关系**。

可得到的结论类型：

| 结论类型 | 示例 | 证据强度 |
|---------|------|---------|
| 相关性 | "推荐率和网站更新正相关" | 弱 |
| 实验性 | "更新案例页面后，推荐率提升6%" | 强 |
| 时间先行 | "排名上升出现在内容变更之后" | 中 |
| 机制解释 | — | 不可得（黑盒） |

### D.2 实验设计规范

每个实验必须包含：

```
[实验注册]
experiment_id: UUID
hypothesis: "如果[操作X]，那么[指标Y]将变化[幅度Z]"
treatment: 具体操作描述
control: 对照条件
metrics: 受影响的指标列表
duration: 预计周期（至少2周）
sample_size: 所需观测次数

[实验执行]
pre_measurement: 实验前的n次观测
intervention: 执行操作
post_measurement: 实验后的n次观测

[结果判定]
effect = post_mean - pre_mean
if effect > 2 * pooled_se → 显著有效
if effect > pooled_se → 趋势性，需延长实验
else → 无效
```

### D.3 可归因的变化阈值

变化至少超过测量误差的2倍，才能归因于操作。

```
只有当 |GEO_Score_t - GEO_Score_{t-1}| > 2 * CI_width 时，
才报告"评分发生变化"。
否则报告"评分稳定"。
```

## Module E: 质量保证

### E.1 测量验证

| 验证项 | 方法 | 频率 | 通过标准 |
|--------|------|------|---------|
| 重测信度 | 相同条件重复测量 | 每天 | 相关系数 > 0.85 |
| 内部一致性 | 类似Prompt的结果一致性 | 每周 | Cronbach alpha > 0.7 |
| 跨模型一致性 | 不同模型排名相关性 | 每周 | Spearman rho > 0.5 |
| 时间稳定性 | 无干预时评分的波动 | 持续 | 标准差 < 5% |

### E.2 偏误清单

| 已知偏误 | 影响 | 缓解措施 |
|---------|------|---------|
| 幸存者偏误 | 只测量已知品牌，忽略未被AI提及的品牌 | 纳入行业清单中的全部企业 |
| 确认偏误 | 倾向报告支持假设的结果 | 预设分析计划，注册实验 |
| 时间偏误 | 不同时间段测量不可比 | 固定时间窗口，同期群设计 |
| Prompt偏误 | 特定Prompt的结果不具代表性 | 多样化Prompt，分层采样 |

### E.3 测量漂移检测

持续监控测量系统的稳定性：

```
if VR(model, query, time_t) - VR(model, query, time_0) > 3 * sigma:
    触发漂移告警
    检查：模型是否更新？环境是否变化？测量协议是否变更？
```

## Module F: 报告与沟通

### F.1 评分报告标准

每次报告GEO评分必须包含：

```
GEO评分: 78
置信区间: [73, 83]
置信等级: 中（基于14天数据，3个模型，42次观测）
测量条件: Q_standard_v2026Q3, ChatGPT/Gemini/Claude
报告生成时间: 2026-08-01 10:00 UTC
下次数据更新: 2026-08-02 10:00 UTC
```

### F.2 局限性声明

所有对外报告必须附带：

> "本评分基于在控制条件下对AI模型输出的统计分析。
> 评分反映的是观测到的推荐模式，不代表AI模型的"真实意见"。
> 评分受测量随机性影响，单次评分变化5分以内可能属于正常波动。"

### F.3 产品交互原则

| 场景 | 交互方式 |
|------|---------|
| 查看当前评分 | 显示点估计+置信区间+置信等级 |
| 查看趋势 | 显示7日移动平均线+个体观测点 |
| 评分发生变化 | 同时显示变化量和置信区间（不误导） |
| 数据不足 | 明确提示"数据积累中"，不显示不可靠的评分 |

## Module C: 负反馈机制

### C.1 为什么需要负反馈

多数平台只收集正反馈（什么有效）。基础设施还必须知道哪里错了。负反馈不是失败记录，而是系统的学习信号。每个错误的推荐、过时的信息、冲突的描述，都是模型优化的起点。

### C.2 负反馈来源与处理

| 来源 | 示例 | 处理方式 |
|------|------|---------|
| 错误推荐 | 推荐了不适合的企业 | 记录三元组(用户,需求,不符合的企业)，下调推荐权重 |
| 过时信息 | 企业已转型但图谱未更新 | 标记数据老化，触发重新验证流程 |
| 冲突信息 | 多个来源描述不一致 | 进入冲突仲裁(数据来源等级 vs 信息时间戳) |
| 负面评价 | 合作评价低于阈值 | 关联到对应企业/能力，下调可信权重 |
| Agent验证失败 | AI Agent发现数据与事实不符 | 自动触发数据重新采集+校验 |

### C.3 负反馈闭环流程

| 步骤 | 动作 | 负责方 |
|------|------|-------|
| 1 | 检测异常(错误推荐/冲突/老化) | Scanner Agent / 评价系统 |
| 2 | 记录负反馈事件(含上下文) | Event Log |
| 3 | 原因分析(为什么错?) | Analysis Agent |
| 4 | 制定修正方案 | Decision Engine |
| 5 | 执行修正(模型/图谱/权重调整) | Context Engine |
| 6 | 验证修正效果 | QA Agent |

## Module H: 推荐透明度

### H.1 推荐原因可解释

AI推荐企业时，必须附带推荐原因：
- “推荐A公司，因为未来公司在该行业被AI提及的频率最高、信任评分达85分、且具备丰富的行业案例”

### H.2 推荐因子权重展示

每次推荐显示各因子的权重分布：
| 因子 | 权重 |
|--------|--------|
| AI可见度 | 35% |
| 信任评分 | 25% |
| 行业相关 | 20% |
| 能力匹配 | 20% |


## Module I: 证据图谱

每个推荐结论都有证据链。推荐企业A的原因：✓ 12个客户案例 ✓ 3个行业认证 ✓ 真实项目反馈 ✓ AI曝光增长记录 ✓ 第三方评价。证据图谱将所有证据结构化、可查询、可验证，形成AI时代的信用基础设施。
