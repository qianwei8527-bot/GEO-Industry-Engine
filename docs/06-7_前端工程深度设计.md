### 2.2 组件数据来源

所有组件不直接调用API，通过父页面传递props:
- 页面: 调用API获取数据
- 组件: 接收props渲染
- 好处: 组件可复用，数据获取逻辑集中在页面层

每个组件文件结构: Props 类型定义 -> 组件函数 -> 导出

## 三、状态管理

### 3.1 策略

不使用Redux/Zustand等全局状态库:
- 页面间: URL参数传递 (书签+分享可用)
- 页面内: React useState/useReducer
- 跨页面缓存: React Context (用户信息/认证状态)
- 服务端缓存: Next.js fetch cache + revalidate

### 3.2 Context层

```typescript
// AuthContext: 用户认证状态
{ user, role, tenant, login, logout }

// ConfigContext: 前端配置
{ featureFlags, theme, locale }
```

## 五、API客户端

### 5.1 统一请求封装

```typescript
// lib/api.ts
async function apiClient<T>(endpoint, options): Promise<T> {
  const res = await fetch(BASE_URL + endpoint, {
    headers: { Authorization: `Bearer ${token}`, ... },
    ...options
  });
  if (!res.ok) throw new ApiError(res.status, await res.json());
  return res.json();
}
```

### 5.2 错误处理

- 401: 自动刷新Token或跳转登录
- 403: 显示权限不足提示
- 404: 显示Not Found页面
- 429: 显示频率限制提示+自动重试
- 5xx: 显示服务错误+重试按钮

### 5.3 请求优化

- 列表页分页: page + page_size
- 搜索防抖: 300ms debounce
- 重复请求去重: SWR/deduping
- 乐观更新: 表单提交先更新UI再确认
