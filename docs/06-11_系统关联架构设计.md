## 一、关联架构总览

GEO-Industry-Engine 的核心价值不是六个独立系统，而是它们之间的关联网络。同一个 GEO Identity 贯穿全部六个系统，Decision Engine 作为中央智能路由，知识图谱作为共享数据基础。

`
                         GEO Identity (Entity)
                              |
         +----------+---------+---------+----------+----------+
         |          |         |         |          |          |
    检测中心      认证中心    产业导航   数据资产    交易市场    产业情报
    (认知)      (信任)      (位置)     (沉淀)      (连接)     (预测)
         |          |         |         |          |          |
         +----------+---------+---------+----------+----------+
                              |
                      Decision Engine
                    (评估/预测/推荐/匹配)
                              |
                    GEO 知识图谱
          (Entity-Capability-Relationship-Event-Evidence-Trust)
`

**核心原则:**
- 同一 Entity 在所有系统中共享身份
- Decision Engine 是唯一评估来源，禁止各系统独立评分
- 事件(Event)是系统间数据流动的触发器
- 每一条关联都是可追溯的（引用 Evidence/Decision Rule）

## 二、GEO身份贯穿模型

Entity 在六大系统中的生命周期:

| 阶段 | 系统 | Entity状态 | 触发事件 | 用户可做 |
|------|------|-----------|---------|---------|
| 0-发现 | 检测中心 | 创建→基础评估 | 用户搜索/系统收录 | 查看GEO位置 |
| 1-认知 | 检测中心 | 生成评估报告 | Decision Engine计算完成 | 查看机会/风险/路线 |
| 2-补充 | 数据资产 | 数据完整度提升 | 用户提交企业信息/证据 | 补充百科/案例/文档 |
| 3-验证 | 认证中心 | 进入审核流程 | 用户申请认证 | 提交认证材料 |
| 4-定位 | 产业导航 | 获得产业坐标 | 认证通过+数据达标 | 查看行业位置 |
| 5-连接 | 交易市场 | 成为可匹配主体 | 认证L2+ | 发布需求/接单 |
| 6-监测 | 产业情报 | 持续监控 | 行业事件/竞品变化 | 接收预警/发现机会 |
| 7-循环 | 检测中心 | 重新评估 | 新数据+新事件触发 | 获得更新后的评分 |

**身份快照(Snapshot)机制:**
- 每次 Decision Engine 重算时自动生成 Identity Snapshot
- 包含: 当前评分、能力列表、关系图谱、认证等级、行业位置、机会/风险
- 历史快照形成 Identity Evolution Timeline（成长轨迹）

## 四、Decision Engine 中央路由

Decision Engine 是唯一评估来源。禁止任何其他模块独立产出评分。

### 4.1 输入来源（从六系统接收）

| 输入 | 来源系统 | 数据类型 | Decision使用 |
|------|---------|---------|-------------|
| Entity基础数据 | 检测中心 | entity_id, type, industry | 评估基准 |
| Certification状态 | 认证中心 | cert_level, trust_score | Trust权重 |
| Industry Position | 产业导航 | industry_rank, market_share | 位置评估 |
| Evidence Count | 数据资产 | total_evidence, quality_score | 证据权重 |
| Transaction History | 交易市场 | order_count, review_avg | 活跃度权重 |
| Risk/Opportunity | 产业情报 | risk_signals, opportunities | 预测调整 |

### 4.2 输出分发（向六系统输出）

| Decision输出 | 目标系统 | 接口 | 触发频率 |
|-------------|---------|------|---------|
| GEO Position Score | 检测中心 | GET /decision/company/{id}/assessment | On-demand |
| Trust Update | 认证中心 | Certification.status 变更 → 写入 Entity.trust | Event-driven |
| Industry Ranking | 产业导航 | GET /decision/industry/{id} | On-demand |
| Gap Analysis | 数据资产 | GET /decision/company/{id} → gaps字段 | On-demand |
| Match Score | 交易市场 | POST /decision/analyze → matching | On-demand |
| Risk Warning | 产业情报 | GET /decision/company/{id} → risks字段 | Scheduled daily |
| Opportunity Alert | 产业情报 | GET /decision/company/{id} → opportunities字段 | Scheduled daily |
| Growth Roadmap | 检测中心 | GET /decision/company/{id} → roadmap字段 | On-request |

### 4.3 可解释性约束

每个 Decision 输出必须附带:
- score: 数值评估结果
- 
eason: 自然语言解释（基于哪些数据得出）
- evidence_refs: 引用的证据ID列表
- 
ule_ref: 引用的YAML配置规则
- improvement_action: 可执行的改进建议

## 五、事件驱动触发链

Event 是系统间数据流动的触发器。所有状态变更都应产生 Event，Event 触发 Context 刷新，Context 刷新触发 Decision 重算。

### 5.1 事件类型与触发链

| 事件类型 | 产生系统 | 触发Context刷新 | 触发Decision重算 | 通知目标系统 |
|---------|---------|:--:|:--:|-----------|
| entity.created | 检测中心 | ✅ Entity | ✅ 新评估 | Navigation,Assets |
| entity.updated | 数据资产 | ✅ Entity | ✅ 重评估 | Detection |
| certification.applied | 认证中心 | — | — | Admin(审核) |
| certification.approved | 认证中心 | ✅ Entity+Ctx | ✅ Trust+Score | Detection,Navigation,Marketplace |
| certification.rejected | 认证中心 | — | — | Detection(通知) |
| evidence.added | 数据资产 | ✅ Entity | ✅ Score | Detection |
| relationship.created | 产业导航 | ✅ Entity+Industry | ✅ Position | Detection |
| transaction.completed | 交易市场 | ✅ Entity+Relationship | ✅ Activity | Intelligence |
| review.submitted | 交易市场 | ✅ Entity | ✅ Trust | Detection |
| industry.event | 产业情报 | ✅ Industry | ✅ 批量重算 | Detection,Navigation |
| risk.detected | 产业情报 | ✅ Entity | ✅ Risk评估 | Detection |

### 5.2 事件处理流程

`
Event产生 → 写入 events表 + analytics_events表
    ↓
Event Router 判断影响范围:
    ├── 影响单个Entity → 刷新该Entity的Context
    ├── 影响Industry → 刷新该行业Context + 所有相关Entity
    └── 全局影响 → 标记全量刷新(延迟批处理)
    ↓
Context Engine: 重算 Context Snapshot
    ↓
Decision Engine: 基于新Context重算评估
    ↓
结果分发: 更新各系统视图
    ↓
用户通知: 推送/邮件/站内信
`

## 六、知识图谱共享层

所有六个系统共享同一套知识图谱，不允许各自维护独立数据副本。

### 6.1 共享实体定义

| 图谱节点 | 范围 | 生产者 | 消费者 |
|---------|------|--------|--------|
| Entity | 全局唯一 | 检测中心(创建), 数据资产(更新) | 全部六系统 |
| Capability | 绑定Entity | 数据资产(声明), 认证中心(验证) | Detection, Navigation, Marketplace |
| Relationship(source→target) | 跨Entity | 产业导航(发现), 交易市场(产生) | Detection, Intelligence |
| Event | 绑定Entity | 全部六系统 | Context, Decision, Intelligence |
| Evidence | 绑定Entity | 数据资产(上传), 认证中心(审核) | Decision, Certification |
| Trust | 绑定Entity | Decision(计算), 认证中心(影响) | 全部六系统 |

### 6.2 知识图谱一致性保证

- Entity ID 全局唯一，一次创建永不改变
- 各系统通过 /api/v1/entities/{id} 获取最新Entity状态
- Capability/Relationship/Evidence的变更通过Event机制广播
- 任何系统修改Entity数据必须写Event日志
- Decision Engine读取的是Context Snapshot，不是直接DB查询

## 七、前端导航互联设计

每个页面必须提供到达关联系统的入口。当前现状: 仅 login↔register 有互链，系统间零互联。

### 7.1 每页互联映射

#### 首页 (/) 
- 出链: 检测中心, 认证中心, 产业导航, 数据资产, 交易市场, 产业情报 (六大入口卡片)
- 入链: 所有页面的返回首页

#### 检测中心 (/detection)
- 出链: /detection/result (评估结果), /certification (申请认证), /assets (补充数据), /navigation (查看产业位置)
- 入链: 首页, /navigation, /intelligence
- 携带参数: entity_id → 各系统

#### 检测结果 (/detection/result)
- 出链: /certification/apply (认证入口, 带entity_id), /assets (补充数据建议, 带缺口列表), /navigation (产业定位, 带industry_id), /intelligence (风险详情)
- 入链: /detection 提交后

#### 认证中心 (/certification)
- 出链: /certification/apply, /detection (查看当前状态), /assets (补充认证证据)
- 入链: /detection 的"去认证"按钮

#### 认证申请 (/certification/apply)
- 出链: /certification/passport/{id} (通过后), /assets (补充证据), /detection (查看评估)
- 入链: /certification

#### 产业导航 (/navigation)
- 出链: /detection (查看某企业详情), /marketplace (发现交易机会), /intelligence (行业情报)
- 入链: 首页, /detection

#### 数据资产 (/assets)
- 出链: /detection (查看评分影响), /certification (提交认证), /marketplace (展示服务)
- 入链: /detection 的"补充数据"建议

#### 交易市场 (/marketplace)
- 出链: /certification (查看服务商认证), /assets (查看企业资产), /navigation (查看产业关系)
- 入链: /navigation 的"找服务商"

#### 产业情报 (/intelligence)
- 出链: /detection (受影响的实体详情), /navigation (行业趋势地图)
- 入链: 首页, /detection 的风险/机会卡片

#### 管理后台 (/admin)
- 出链: 审核页面(/certification/review-pending), 配置管理, 统计面板
- 入链: 仅管理员

### 7.2 页面间传参约定

| 参数 | 传递场景 | 格式 |
|------|---------|------|
| entity_id | 任何系统跳转时携带 | UUID |
| industry_id | 导航→检测, 情报→导航 | UUID |
| gap_types | 检测→资产(建议补充) | comma-separated list |
| cert_level | 认证→检测(新等级) | L0-L4 |

## 九、数据飞轮闭环验证

### 9.1 飞轮检查点

| 飞轮环节 | 检查项 | 验证方式 |
|---------|--------|---------|
| 数据进入 | Entity创建后是否在全部六系统可见 | 查询 /entities/{id} |
| 认知形成 | Context Engine是否基于最新数据 | Context Snapshot时间戳 |
| 评估输出 | Decision Engine是否引用Context (非直接DB) | Decision日志 |
| 建议生成 | 建议是否有具体改进动作 | improvement_action字段非空 |
| 用户行动 | 用户行为是否产生Event | analytics_events表 |
| 数据反哺 | 新Event是否触发Context刷新 | Event→Context延迟<5s |
| 评分更新 | 新数据是否导致Decision重算 | Score历史版本 |

### 9.2 飞轮健康指标

| 指标 | 计算方式 | 健康阈值 |
|------|---------|---------|
| 关联密度 | 有≥3个系统关联的Entity占比 | ≥60% |
| 数据新鲜度 | Context Snapshot距上次更新<24h 的Entity占比 | ≥80% |
| 建议采纳率 | 用户执行了 improvement_action 的比例 | ≥15% |
| 飞轮闭环率 | Entity从创建到产生交易的比例 | ≥5% |
| Event传播延迟 | Event产生→Decision重算的端到端时间 | <10s |

## 十、关联变更影响评估

每当修改某个系统的API或数据模型时，必须评估对其他5个系统的影响:

| 变更类型 | 影响范围 | 检查清单 |
|---------|---------|---------|
| Entity新增字段 | 全部六系统 | 所有consumer是否兼容新字段 |
| Decision模型变更 | Detection+Navigation+Marketplace | 结果格式是否向后兼容 |
| 认证等级调整 | Detection+Marketplace | Trust计算是否需要重新标定 |
| 行业分类变更 | Navigation+Intelligence+Detection | 历史数据迁移方案 |
| Event类型新增 | Context+Intelligence | Router是否识别新类型 |
