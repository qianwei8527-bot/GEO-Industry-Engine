# 恒域世界-GEO 第一条真实域主价值链

> 版本：V10-P0 | 状态：已实施 | 更新：2026-08-03

## 一、闭环链路

```text
真实主体注册
→ 创建/认领企业域、品牌域
→ 导入并授权自有数据
→ 建立真实 GEO 目标、问题与需求
→ 创建 GEO Project
→ 调用已有检测、Agent、Skill 或外部 AI 工具
→ 保存诊断、内容、报告、引用与执行过程
→ 记录发布或交付
→ 监测结果
→ 形成 Evidence / EvidenceClaim / Outcome
→ 沉淀到品牌域成长时间线与数据资产清单
```

## 二、最小可操作闭环

域主工作台位于 `frontend/src/app/realm/page.tsx`，后端入口：

- `POST /api/v1/auth/register`
- `POST /api/v1/realm/enterprises`
- `POST /api/v1/realm/brands`
- `POST /api/v1/realm/{entity_id}/claim`
- `POST /api/v1/realm/{entity_id}/authorizations`
- `POST /api/v1/realm/{entity_id}/assets`
- `POST /api/v1/realm/{entity_id}/evidence`
- `POST /api/v1/geo-projects`
- `POST /api/v1/geo-projects/{project_id}/work-items`
- `POST /api/v1/geo-projects/{project_id}/tool-executions`
- `POST /api/v1/geo-projects/{project_id}/artifacts`
- `POST /api/v1/geo-projects/{project_id}/outcomes`

- `GET /api/v1/geo-projects/{project_id}/timeline`
- `GET /api/v1/geo-projects/{project_id}/assets`

## 三、关键设计

1. 项目本身不是 Universal Fact：`GeoProject.may_affect_real_metrics=False`。
2. 域主提交的 Evidence 默认 `observed`，不能自动变成 `verified`。
3. 工具执行记录固化 provider、tool、model、version、input/output manifest、source_fact_ids、config_version、config_hash、citations、cost、执行状态。
4. Outcome 只有挂接已 verified 的 `EvidenceClaim` 才会投影为 verified；否则保持 pending/claimed。
5. 连接、项目完成、accepted/completed 均不直接修改 Reputation。

## 四、首条价值链验收

API 冒烟已跑通完整链路：注册 → 建企业域 → 授权 → 资产 → 证据 → 关系 → GEO 项目 → 工作项 → 工具执行 → 产物 → 结果 → 时间线 → 资产清单。

进入真实域主阶段前，还需要：治理员验证 EvidenceClaim、真实 AI 工具接入、发布/交付数据回填。
