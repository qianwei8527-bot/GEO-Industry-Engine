# GEO-Industry-Engine 可扩展性与弹性设计

## 一、可扩展性设计原则

### 1.1 配置驱动扩展

凡是未来可能变化的规则优先配置化，不修改代码即可扩展：

| 扩展点 | 配置位置 | 扩展方式 |
|--------|---------|---------|
| 评分模型参数 | config/scoring/*.yaml | 修改YAML -> 热加载 |
| 认证等级规则 | config/certification/levels.yaml | 新增等级定义 |
| 产业分类 | config/competitive/intelligence.yaml | 新增行业节点 |
| 定价套餐 | config/pricing/plans.yaml | 新增plan条目 |
| 权限矩阵 | config/pricing/permissions.yaml | 新增角色/权限映射 |
| Agent行为 | 数据库 + YAML | 新增Agent注册+Prompt配置 |

### 1.2 插件化架构

预留插件点：

| 插件类型 | 接口 | 示例 |
|---------|------|------|
| 评分模型插件 | ScoringModelBase | 自定义行业评分算法 |
| 数据源插件 | DataSourceBase | 接入新的企业数据源 |
| Agent插件 | BaseAgent | 第三方Agent注册 |
| 认证审核插件 | ReviewPluginBase | 自定义审核规则 |
| 通知插件 | NotificationBase | 邮件/短信/Webhook |

### 1.3 多租户多产业复制

同一套引擎可根据行业配置快速复制：医疗GEO使用不同的评分配置，教育GEO使用不同的权重，不修改代码。

配置目录结构预留：
```
config/scoring/industry/healthcare.yaml
config/scoring/industry/education.yaml
config/scoring/industry/manufacturing.yaml
```

## 二、弹性设计

### 2.1 服务降级

| 场景 | 降级策略 | 影响 |
|------|---------|------|
| Decision Engine 超载 | 返回缓存结果 | 报告非实时 |
| 外部AI平台不可用 | 仅传统搜索评分 | 缺少AI可见度维度 |
| Agent服务不可用 | 返回静态推荐 | 缺少动态分析 |
| 数据库只读 | 切换只读副本 | 禁止写入操作 |

### 2.2 缓存策略

| 缓存层 | TTL | 失效策略 |
|--------|-----|---------|
| 企业GEO Score | 24h | 有新Event时失效 |
| 行业指数 | 48h | 批量更新触发 |
| 认证状态 | 实时 | 无缓存 |
| 排行榜 | 6h | 定时重算 |

### 2.3 水平扩展

| 组件 | 扩展方式 | 状态 |
|------|---------|------|
| API Server | 无状态，直接加实例 | 设计预留 |
| Context Engine | 计算密集型，独立Worker池 | 设计预留 |
| Decision Engine | 可异步批量计算 | 设计预留 |
| PostgreSQL | 读写分离 + 连接池 | 设计预留 |
| Redis | 集群模式 | 设计预留 |

### 2.4 弹性指标

- API 可用性目标: 99.9% (月)
- P99 延迟: < 2秒
- 并发容量目标: 1000 QPS (单实例)
- 故障恢复时间: < 5分钟
