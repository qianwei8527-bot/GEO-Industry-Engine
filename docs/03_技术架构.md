# GEO产业引擎 — 技术架构

## 整体架构

```
                     Frontend (Next.js)
     AI增长中心 │ 产业导航 │ 交易市场 │ 数据中心 │ 生态中心
                            │
                      API Gateway (FastAPI)
                Auth · Rate Limit · Router · Cache
              │          │          │          │
        AI Growth   Industry    Market      Data
         Service     Nav Ser    Place Ser   Center Ser
              │          │          │          │
              └──────────┴──────────┴──────────┘
                            │
                    AI Agent Runtime
         CEO │ CTO │ Product │ Industry │ Scanner
         Content │ Data │ Market │ Sales │ QA
                            │
                  ┌────────┴────────┐
             PostgreSQL    Neo4j    Vector DB    ES
```

## 数据库选型

| 数据库 | 用途 |
|--------|------|
| **PostgreSQL** | 用户、企业、交易、内容等结构化数据 |
| **Neo4j** | 产业知识图谱（行业-企业-服务商关系） |
| **Vector DB** | AI语义搜索、Prompt匹配、内容相似度 |
| **ElasticSearch** | 全文搜索、日志分析、数据分析 |

## 系统要求

### 模块化
- 每个核心系统作为独立微服务
- 通过API Gateway统一入口
- 服务间通过消息队列异步通信

### 数据资产化
- 所有业务数据通过统一数据管道进入数据湖
- 结构化数据 → PostgreSQL
- 关系数据 → Neo4j
- 向量数据 → Vector DB
- 全文数据 → ES

### 数据库化
- 数据资产中心提供统一数据API
- 支持多维数据分析
- 支持外部数据导入

### 可扩展
- 水平扩展：服务无状态化
- 垂直扩展：数据库读写分离
- 功能扩展：插件化架构

### 可自动更新
- CI/CD流水线
- 数据库自动迁移
- 模型自动训练管道

### 持续迭代
- A/B测试框架
- 功能开关
- 灰度发布

### Agent可调用
- 所有服务提供Agent友好的API
- 工具定义（Function Calling规范）
- Agent间通信协议

### 支持未来商业化
- 多租户架构
- 计费与配额系统
- SaaS订阅管理

## 非功能需求

| 指标 | 目标 |
|------|------|
