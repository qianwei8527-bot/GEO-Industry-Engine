## 2. 后端实现

### 2.1 计划状态机

后端强制：

```text
project_created → plan_draft → plan_confirmed → plan_active → plan_completed
```

任务状态：

```text
planned → in_progress → blocked → in_progress → completed
```

- 只有 `plan_draft` 可确认，确认必须显式 `confirmed=true`。
- 只有确认后的计划才生成 `ProjectWorkItem`。
- 重复确认不会重复生成任务；并发确认最终只有一套任务。
- 所有修改要求 `expected_version`；计划历史通过 `ProjectArtifact` 版本保存。

### 2.2 ProjectPlanService

新增 `backend/app/services/project_plan_service.py` 与 `config/universe/project_plan.yaml`：

- 输入仅使用已确认定位、项目目标和域主选定的工作流来源。
- 平台通用模板明确 `truth_scope=inferred`、`source_type=platform_seed`、`owner_confirmed=false`。
- 同输入、同模板、同配置产生相同 `plan_hash`。
- 缺失负责人、日期等进入 `unknown_items`，不补造。
- 外部 AI 未配置不影响本地计划草稿生成。
- 任务依赖、日期顺序、progress 边界、completed=100% 均由后端校验。

### 2.3 API

新增 `backend/app/api/v1/project_plans.py`：

- `GET /api/v1/project-plans/{project_id}`
- `POST /api/v1/project-plans/{project_id}/generate`
- `PUT /api/v1/project-plans/{project_id}/draft`
- `POST /api/v1/project-plans/{project_id}/confirm`
- `PATCH /api/v1/project-plans/{project_id}/tasks/{task_id}`
- `GET /api/v1/project-plans/{project_id}/export.csv`

无权限与不存在对象统一返回 404 `resource not found`，不泄露存在性。
