## 一、设计说明


---

## 用户体验设计原则

| 原则 | 描述 | 体现 |
|------|------|------|
| 认知闭合 | 用户进入后必须能找到答案 | 检测中心四层报告闭环（身份→机会→风险→路径） |
| 渐进披露 | 先简后繁，按需深入 | 快速检测(30s)→完整报告→深度分析 |
| 角色适配 | 不同角色看到不同首页 | 7角色差异化首页入口 |
| 数据可视化 | 评分/排名用图表而非数字 | 雷达图/趋势线/热力图 |
| 行动导向 | 每个页面都有下一步操作 | 报告底部推荐动作按钮 |

本文件定义 7 类用户角色进入 GEO-Industry-Engine 后的完整任务路径。每条路径标注：
- **页面跳转顺序**：用户依次访问哪些页面
- **数据流转**：每一步触发哪些 API → 引擎 → 数据模型
- **状态变化**：用户/GEO身份在每一步的状态跃迁

路径非强制路由，代表系统为每类角色设计的最优体验链路。

## 二、企业用户流程

### 2.1 首次使用：认知自己

```
未登录状态
     │
     ▼
┌──────────────────────┐
│ 首页                  │  看到飞轮视觉，理解GEO产业生态
│ 输入企业名称，点击评估   │
└──────┬───────────────┘
       │ POST /detection/quick
       │ → Decision Engine → Entity+Trust
       ▼
┌──────────────────────┐
│ 快速检测结果（浮层）      │  简版GEO身份卡：企业名/行业/等级/可见度
│ "你的企业GEO等级: B+"   │  状态变化: 阶段0(未知)→阶段1(被发现)
│ [查看完整报告]          │
└──────┬───────────────┘
       │ 点击"查看完整报告"
       ▼
┌──────────────────────┐
│ 评估报告 /detection/result │  四层完整展示
│ ├ 第一层：我是谁？       │  GET /context/company/{id} → Entity+Context
│ │  GEO身份卡            │  GET /decision/geo-score → Score+Rank
│ │  行业排名 Top 18%     │
│ ├ 第二层：机会在哪？     │  GET /decision/opportunity → Opportunity
│ │  3个增长机会          │
│ ├ 第三层：风险是什么？    │  GET /decision/risk → RiskAlert
│ │  竞品变化 +45%        │
│ └ 第四层：该怎么办？     │  GET /decision/roadmap → Roadmap
│    5步行动路线          │
└──────┬───────────────┘
       │ 发现"数据完整度仅58%"
       ▼
┌──────────────────────┐
│ 数据资产中心 /assets    │  数据完整度详情
│ ├ 完整度雷达图          │  GET /entities/{id}/quality → Entity+Evidence
│ ├ 缺口列表（按影响力）    │  GET /decision/data-gaps → GapList
│ └ [补充数据] [申请认证]  │  状态变化: 阶段1→阶段2(被理解)
└──────┬───────────────┘
       │ 点击"申请认证"
       ▼
┌──────────────────────┐
│ 认证申请 /certification/apply │
│ ├ 选择认证等级 L2       │  GET /certification/levels
│ ├ 上传证据材料          │  POST /evidence
│ ├ AI预审               │  POST /certification/ai-review
│ └ [提交审核]           │  POST /certification/apply
└──────────────────────┘
       │
       用户注册登录（如未注册）
       │
       ▼
┌──────────────────────┐
│ 审核进度 /certification/review-status │
│ ├ AI审核: 通过          │  GET /certification/review/{id}/ai
│ ├ 人工审核: 进行中       │  GET /certification/review/{id}/manual
│ └ 预计3个工作日内完成     │  状态变化: 阶段2→阶段3(被认可)
└──────────────────────┘
```

**首次使用完整路径：** 首页 → 快速检测 → 评估报告 → 数据资产 → 认证申请 → 审核进度
**数据流：** Decision/Context → Entity/Trust/Evidence → Certification
**状态跃迁：** 阶段0→1→2→3

### 2.2 回访：持续优化

```
登录后首页（显示"我的GEO位置"卡片）
     │ 看到变化提示："你的可见度本月 +8"
     ▼
检测中心首页 /detection
     │
     ▼
评估报告 /detection/result
     │ 关注趋势变化（GEO Growth Timeline）
     │ GET /decision/growth-timeline/{id}
     │
     ▼

     │
     ▼

     │ GET /decision/geo-score/{id}（前后对比）
     │ 状态变化: 阶段6(持续优化) 循环

```

     │ POST /marketplace/contact

## 三、个人用户流程

### 3.1 建立职业身份

```
首页
     │ 选择"个人"角色入口
     ▼
检测中心 /detection
     │ 输入姓名+技能关键词，快速评估
     │ POST /detection/quick（person类型）
     ▼
评估报告
     │ GEO个人身份卡：姓名/技能标签/影响力排名
     │ 状态变化: 阶段0→阶段1
     ▼
认证中心 /certification
     │ 选择"个人"对象类型
     │ 选择等级: L2（GEO从业者）或 L3（GEO专家）
     ▼
认证申请 /certification/apply
     │ 上传能力证明（作品/证书/项目经验）
     │ POST /evidence
     │ AI预审 → 提交
     ▼
审核进度 → 认证通行证 /certification/passport/{id}
     │ GEO个人身份卡（完整版）
     │ 认证等级徽章 + 能力标签
     │ 状态变化: 阶段1→阶段3
     ▼
产业导航 /navigation
     │ 查找行业机会
     │ 状态变化: 阶段3→阶段4(被连接)
```

**完整路径：** 首页 → 检测中心 → 认证中心 → 认证申请 → 认证通行证 → 产业导航
**状态跃迁：** 阶段0→1→3→4

### 3.2 寻找职业机会

```
认证通行证（已获得L3认证）
     │ 点击"发现机会"
     ▼
产业导航 /navigation → 搜索行业/技能关键词
     │ GET /industries/search
     ▼
查看相关企业和服务商
     │
     ▼
交易市场 /marketplace
     │ 查看需求列表 → 匹配自己能力
     │ GET /marketplace/demands
     ▼
表达意向
     │ POST /marketplace/interest
```

## 四、GEO服务商流程

### 4.1 建立可信身份

```
首页
     │ 选择"服务商"角色入口
     ▼
认证中心 /certification
     │ 选择"服务商"对象类型

     ▼

     │ GEO服务商身份卡
     │ ┌─────────────────────┐
     │ │ 公司A                │
     │ │ GEO服务商 Lv3        │
     │ │ 能力: 内容优化 策略   │
     │ │ 案例: 35个           │
     │ │ 可信度: 92           │
     │ │ 行业: 教育/医疗/制造  │
     │ └─────────────────────┘
     │ 状态变化: 阶段0→阶段3

### 4.2 获取客户

```
认证通行证 → 点击"进入交易市场"

     │ 设置服务展示

     │ POST /marketplace/interest
     │ 状态变化: 阶段4(被连接)
     ▼
合作达成 → 交易 → 评价
     │ POST /marketplace/review
     │ 评价反哺认证等级
     │ 状态变化: 阶段5(被放大)→阶段6(持续优化)

## 九、跨角色共享流程

### 9.1 飞轮闭环（所有角色）

```
数据进入（企业注册/认证/补充证据/交易/评价）
     │
     ▼
Entity + Capability + Relationship + Event + Evidence 增长
     │
     ▼
Context Engine 重新计算产业上下文
     │
     ▼
Decision Engine 更新评分/排名/机会/风险
     │
     ▼
用户看到变化（评分上升、排名变化、新机会出现）
     │
     ▼
用户采取行动（补充数据、申请认证、建立合作）
     │
     ▼
更多数据进入 → 循环
```

### 9.2 GEO身份演化路径（所有实体类型）

```
创建 GEO 身份 → 阶段0（未知）
     │
     ▼ 补充基础数据
数据完整度 > 40% → 阶段1（被发现）
     │
     ▼ 补充关系+证据
数据完整度 > 60% + 有关系数据 → 阶段2（被理解）
     │
     ▼ 通过认证
获得 L2 以上认证 → 阶段3（被认可）
     │
     ▼ 建立产业连接
有关系增量 + 合作事件 → 阶段4（被连接）
     │
     ▼ 产生交易
有交易记录 → 阶段5（被放大）
     │
     ▼ 持续反馈
数据反哺 → 阶段6（持续优化）→ 循环回到阶段1重新评估
```

## 十、流程中的关键状态节点

| 节点 | 触发条件 | 状态变化 | 下游影响 |
|------|---------|---------|---------|
| 首次检测 | 用户输入企业名称 | 阶段0→1 | 创建 Entity + 生成初始评分 |
| 数据补充 | 上传证据/补充能力 | 阶段1→2 | Context 重新计算 → 评分更新 |
| 认证通过 | 审核通过 | 阶段2→3 | Trust Score +20~40 → 认证标识全局展示 |
| 首次连接 | 表达合作意向 | 阶段3→4 | Relationship 新增 → 产业导航更新 |
| 首次交易 | 订单完成 | 阶段4→5 | Order 记录 → 评价体系启动 |
| 定期重评 | Decision Engine 定时任务 | 阶段5→6(循环) | 全部评分更新 → 新机会/新风险发现 |
