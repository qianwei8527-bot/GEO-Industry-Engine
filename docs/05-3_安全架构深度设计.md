## 一、密钥管理体系

| 密钥类型 | 存储方式 | 轮换周期 | 访问控制 |
|---------|---------|:------:|---------|
| JWT 签名密钥 | KMS / 环境变量（开发） | 90天 | 仅 CI + 生产服务器 |
| API Key | bcrypt hash 存储，原文不存 | 按需 | 用户自助重置 |
| 数据库密码 | 环境变量 / Secrets Manager | 180天 | 仅应用服务器 |
| 加密密钥(AES-256) | KMS 托管，应用不持有 | 365天 | 仅 KMS 授权服务 |
| TLS 证书 | 自动续期(Let's Encrypt) | 90天 | 自动 |

密钥泄露响应：立即轮换 → 撤销旧密钥 → 审查访问日志 → 通知受影响用户。

## 二、审计日志方案

```
audit_logs 表：
├── id, timestamp
├── actor_id, actor_type (user/admin/system)
├── action (create/read/update/delete/export)
├── resource_type, resource_id
├── old_value, new_value (JSON)
├── ip_address, user_agent
└── trace_id (关联请求链)

查询：ELK 索引 → 管理后台"/admin/audit" → 按时间/用户/操作筛选
保留：热数据 90天(ES) → 冷数据 7年(S3/OSS归档)
```

## 三、GDPR 合规展开

| GDPR 条款 | 实现方式 |
|-----------|---------|
| 数据可携(Art.20) | 用户可导出全部 GEO 身份数据（JSON格式） |
| 被遗忘权(Art.17) | 删除个人数据 + 匿名化统计贡献 + 30天处理窗口 |
| 同意管理(Art.7) | 注册时明示同意 + 可随时撤回 + 撤回不影响已处理数据 |
| 数据处理记录(Art.30) | 自动生成处理活动记录 |
| DPO | 指定数据保护官联系方式（公开页面） |
| 数据泄露通知(Art.33) | 72小时内通知监管机构 + 通知受影响用户 |

## 四、渗透测试策略

| 测试类型 | 频率 | 范围 |
|---------|:--:|------|
| 自动化扫描(OWASP ZAP) | 每次 CI | 所有 API 端点 |
| 依赖漏洞扫描(Dependabot) | 每日 | Python/Node 依赖 |
| 手动渗透测试 | 每季度 | 认证/授权/注入/SSRF |
| 源代码审计 | 每半年 | 核心模块 |

## 五、安全事件响应

```
检测（监控告警/用户报告/渗透发现）
    │
    ▼
分级（P1数据泄露 / P2权限绕过 / P3低危漏洞）
    │
    ▼
P1: 15分钟内响应 → 隔离受影响系统 → 修复 → 通知用户 → 事后复盘
P2: 4小时内响应 → 修复 → 发布补丁
P3: 下一个Sprint修复
```

## 六、数据分类与保护级别

| 级别 | 数据示例 | 加密 | 访问控制 | 审计 |
|:--:|---------|:--:|:------:|:--:|
| 公开 | 产业统计、企业公开信息 | — | 无需认证 | — |
| 内部 | 评分算法参数、配置 | 传输加密 | 员工+服务账号 | ✓ |
| 敏感 | 企业详细数据、个人身份 | 传输+存储加密 | 角色+租户隔离 | ✓ |
| 机密 | 密码、API Key、支付信息 | 传输+存储+AES-256 | 最小权限 | ✓ |
