## 1. 架构冻结

《17-2 恒域世界 V10.6 整体重构细节设计方案（修正版）》已更新为“V10.6 正式冻结版，进入第一刀实施”，并固化：

- 4 个应用面：域主工作台、公共世界与客户协作端、平台运营后台、治理审计台。
- 10 个中台能力域、3 个技术底座、6 种页面模板。
- 6 种模块状态：loading / empty / partial / blocked / error / no-permission。
- 5 级 truth scope：verified / observed / inferred / unknown / simulation。
- 低、中、高三级授权，外加禁止级。

V10.6 作为上位架构；V10.5 继续作为 AI 启动、执行计划与问题库专项指令。本轮没有建立与现有体系平行的路由、权限、Task、Evidence、Outcome、Realm 或数据模型。

- `RealmDataAuthorization` 已有 `authorization_code`、`valid_until`、`status/revoked_at`、`entity_id` 和审计记录，可安全复用为公共资料提交令牌。
- 本轮未新增表结构，未创建迁移。

### 预计修改文件

- 前端：统一 AppShell、设计令牌、公共资料提交页、owner 令牌面板、查询层、测试。
- 后端：Intake 服务新增公共安全提交协议、Intake API 新增端点、Realm 治理配置允许 `intake_submission` 作用域。

### 是否需要迁移

不需要。公共提交令牌复用 `RealmDataAuthorization`，草稿和提交复用现有 `ClientIntake` 与 `IntakeAnalysis`，使用 `metadata_json` 记录令牌绑定、提交者范围、去重哈希和队列状态。

## 3. 实现内容

### 统一 Shell

新增 `AppShell`，支持：

- `applicationSurface`：owner / public / operations / governance 配置协议。
- NavRail、ContextBar、主内容区、可选 StatusStrip、可选右侧 Drawer。
- Realm 上下文、用户与权限上下文、响应式布局。
- operations 与 governance 只冻结协议，不创建空壳页面。

owner 和 public 均复用同一套 `AppShell`；旧页面与旧路由未删除。

### 设计系统

- 新增 `v106-app-shell` 作用域令牌：主色、中性色、语义色、6px/8px 圆角、4/8/12/16/24 间距、system-ui + 中文回退。
- 复用并扩展六种模块状态，新增 `no-permission` 别名。
- 复用五级 `TruthBadge`。
- 新增 `DataSourceBadge`、`StatusStrip`、`ApprovalItem`。

### 公共资料提交入口

目标路径：`/intake/{secure_token}`。

- 后端用 `RealmDataAuthorization.authorization_code` 解析绑定的 Realm，不信任前端传入的 `realm_id`。
- Token 有有效期、可撤销、不可枚举（高熵授权码），只能访问绑定 Realm。
- 提交者范围与关键操作写 `AuditLog`。
- 草稿、正式提交、去重哈希与限流均基于现有 Intake 记录与 `metadata_json`，无新模型。
- 文件类型、大小、文件名与内容安全校验复用现有 `IntakeService._save_files` 与魔术字节校验。
- 公开 URL 复用现有 SSRF 防护 `validate_url`。

### 真实状态覆盖

- loading：入口加载骨架。
- empty：无草稿且无提交。
- partial：已有草稿时明确列出缺失字段；提交后存在 unknown 字段时显示“需要补充资料”。
- blocked：Token 过期等不可继续场景显示阻塞；外部 AI 未配置显示 partial/warning，本地提取仍可继续。
- error：入口加载失败、文件解析失败。
- no-permission：Token 无效、撤销或作用域不匹配。
- 上传校验失败：前端即时提示，后端再次校验并返回 rejected 清单。
- Token 无效/过期：后端返回明确错误码。
- 文件解析失败：公共端展示真实 `parse_status` / `parse_error`，不隐藏 rejected 文件。
- AI Key 缺失：显示“外部 AI 未配置”，不生成模拟 AI 分析。
- AI 分析处理：同步本地结构化提取使用 `processing` -> `completed`，不再伪装 queued。
- AI 分析失败：无可用文字时状态为 `analysis_failed`。
- 等待域主确认：提交成功返回 `needs_confirmation`，刷新后状态不丢失。

## 5.1 复审修正

- `AppShell` 增加 Feature Flag、Realm 上下文和用户/权限上下文，owner 与 public 均传入真实上下文。
- 公共提交页新增 `partial` 与“需要补充资料”状态，展示 AI 提取后的 unknown 字段。
- 公共提交页展示 rejected / parse_failed 文件清单。
- 后端公共上下文返回 `latest_analysis`，前端可读取真实字段状态。
- 修正草稿保存时清空字段不生效的问题：清空后保存会真实置空。

## 5.2 R1.1 安全与真实性复审修正

- 公共 Token 改为 `secrets.token_urlsafe(32)`，至少 256 bit；`intake_submission` 强制 `valid_until`，并校验 `valid_from`、撤销、作用域。
- AuditLog 只记录 `intake_authorization:{id}` 与脱敏元数据，不再写入完整 Token 或原始客户问题。
- 域主列表只显示掩码 Token；完整链接仅创建成功时展示一次。本轮截图涉及的所有旧 Token 已撤销。
- 新增 Token/IP 原子限流：Redis 可用时使用 Redis Lua 固定窗口；开发/测试环境不可用时使用进程内 asyncio 锁回退，production 返回 503；GET、草稿、提交分别限流。
- 后端强制累计最多 5 个文件并限制累计容量；上传改为分块读取并限容，不再先完整读入内存。
- 未同意“服务器暂存授权”前拒绝保存草稿；记录 `consent_at` 与 `policy_version`。
- “AI 分析排队”文案和 queued 状态已移除，改为真实的 `processing` / `completed`。
- 同一 Token 提交使用行锁串行化，并发双提交只有一个成功。
- 公共 API 改为精简 DTO：不再返回 `extracted_text`、`metadata_json`、内部 Realm ID 等不必要字段。
- 提交成功标题自动滚动到可视区；Realm 中文名称测试数据编码已修正。
- V10.6 协议导航改为冻结的六入口，并标记 `planned/disabled`，不创建空壳页面。

## 5.3 R1.2 最终收口修正

- 超大文件不再静默截断：上传读取器明确抛出 413，超过 10MB 的文件不保存、不解析。
- 公共分析 DTO 统一为顶层 `fields`，移除双套 `analysis_json.fields`；`PublicIntakeFile` 不再声明后端未返回的 `sha256`。
- 创建接口返回完整 `authorization_code`；workspace/list 只返回 `authorization_code_masked`，前端列表不再持有完整 Token。
- 草稿保存成功后清空本地新增文件；页面区分“已暂存文件”与“本次新增文件”，正式提交不会重复发送已暂存文件。
- 限流改为 Redis Lua 原子固定窗口，只在首次 INCR 设置 TTL；IP-only 与 Token-only 分别限流；无效 Token 也在数据库查询前按 IP 限流；production 下 Redis 不可用返回 503，不回退到多进程内存。
- 同一 Realm 可创建多个客户 Token，支持客户/用途标签，各自一次提交、独立撤销和独立有效期。
- 截图术语统一为 `partial-ai-missing`。

## 5.4 模拟闭环基础设施打通

- 新增模拟闭环 API：`POST /api/v1/simulation/loops/run`、`GET /api/v1/simulation/loops/latest`。
- 新增模拟闭环服务：模拟客户资料 → 本地结构化提取 → 模拟定位结论 → 模拟项目 → 模拟执行计划。
- 所有模拟记录明确标记 `simulation`；Evidence 使用 `synthetic`，项目和计划使用 `synthetic`，`may_affect_real_metrics=False`，不写入真实关系或 Reputation。
- 模拟闭环故意保留 unknown 字段，用于验证 partial / 待补充状态。
- 域主“客户与定位”页面新增模拟闭环面板，可运行并查看基础设施链路状态。
- 代码连接注册表补充模拟闭环 API，并将能力市场状态修正为 `reserved`。
- 新增模拟闭环后端测试 2 项：全链路标记与权限边界。

## 6. 剩余缺口与后续影响

- 当前“AI 分析”是真实本地结构化提取，不使用外部模型；外部 AI Key 缺失时显示 partial，不伪造 AI 结论。
- 本地提取仍为同步处理；后续如需外部 AI 异步队列，应接现有 Event Backbone / Queue。
- 令牌以 URL 形式发给提交者，属于 bearer 型能力；生产环境建议增加来源站点/CSRF/Origin 校验，并缩短默认有效期。
- 本轮未新增支付、市场、政策、行业态势和共同治理功能。
