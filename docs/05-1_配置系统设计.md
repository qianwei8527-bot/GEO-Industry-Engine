## 一、配置系统定位

配置系统是 GEO-Industry-Engine 的**可调控中枢**。所有业务规则（评分权重、认证等级、定价策略、匹配逻辑、情报阈值）均通过 YAML 配置驱动，禁止硬编码。

核心目标：同一套引擎，切换配置即可适配不同产业（医疗 GEO、教育 GEO、金融 GEO），不修改一行代码。


## 三、配置加载机制

### 3.1 加载流程

```
应用启动
    │
    ▼
ConfigLoader 扫描 config/active/ 目录
    │
    ▼
读取每个 YAML → 校验 schema_version
    │ schema_version 不匹配 → 警告日志（允许继续）
    ▼
解析为 Pydantic 模型 → 注入 ConfigRegistry（全局单例）
    │
    ▼
各引擎通过 ConfigRegistry.get("scoring/geo_visibility") 获取配置
```

### 3.2 热加载

管理后台 `/admin/config` 更新 YAML 后：
```
PUT /admin/config/scoring/geo_visibility
    │
    ▼
写入文件 → ConfigRegistry.reload("scoring/geo_visibility")
    │
    ▼
Decision Engine 收到 ConfigChangeEvent → 重新计算受影响实体的评分
    │
    ▼
缓存失效 → 下次请求使用新配置
```

### 3.3 多产业配置

```
# 医疗GEO专用配置
config/experiments/medical_v2.1/scoring/geo_visibility.yaml:
  weights:
    entity_quality: 0.30     # 医疗更看重资质
    evidence_score: 0.30     # 证据权重更高
    capability_match: 0.15
    relationship_density: 0.10
    recency: 0.15

# 教育GEO专用配置
config/experiments/education_v1.0/scoring/geo_visibility.yaml:
  weights:
    entity_quality: 0.20
    evidence_score: 0.20
    capability_match: 0.25   # 教育更看重能力标签
    relationship_density: 0.20
    recency: 0.15
```

验证通过后移入 `config/active/`，切换产业只需替换 active 目录下的配置包。

## 四、配置与引擎的耦合关系

| 配置目录 | 读取方 | 影响范围 |
|---------|--------|---------|
| scoring/* | Decision Engine | 所有评分、排名、机会、风险计算 |
| certification/* | Certification 模块 + AI审核 | 认证等级、权限解锁、审核规则 |
| pricing/* | Subscription 模块 + 前端 | 套餐展示、权限校验、支付规则 |
| marketplace/* | Marketplace 模块 | 服务分类、匹配权重 |
| competitive/* | Intelligence 模块 | 竞品监控、机会发现、风险预警 |
| analytics/* | Analytics 模块 | 事件采集、数据保留 |

每个配置变更只影响其对应引擎，不产生跨引擎副作用。

## 五、配置校验规则

ConfigLoader 加载时执行校验：

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| schema_version | 必须存在 | 拒绝加载 |
| 权重总和 | scoring 类配置的 weights 总和 = 1.0（容差 ±0.01） | 拒绝加载 |
| 必填字段 | 根据 Schema 校验 | 拒绝加载 |
| 类型校验 | 根据 Schema 校验（integer/float/string/boolean） | 拒绝加载 |
| 引用完整性 | 配置中引用的 ID（如 industry_id）必须在数据库中存在 | 警告日志 |
| 阈值范围 | 评分阈值在 [0, 100] 区间 | 拒绝加载 |

## 六、配置变更审计

每次配置变更（通过管理后台或直接文件修改）记录：

```yaml
config_change_log:
  timestamp: "2026-07-28T16:00:00Z"
  changed_by: "admin@geo-industry.com"
  file: "scoring/geo_visibility.yaml"
  change_type: "weight_update"
  old_values: {entity_quality: 0.25}
  new_values: {entity_quality: 0.30}
  reason: "医疗产业专项调优"
```

变更日志保留 90 天，管理员可在后台查看和回滚。
