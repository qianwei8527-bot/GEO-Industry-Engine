# 恒域世界 V10.6 整体重构细节设计方案（修正版）

> 上位依据：《恒域世界 V10.6：四阶段演进架构总纲（含参考平台）》
> 设计状态：V10.6 正式冻结版，进入第一刀实施
> 设计原则：4 个应用面、10 个中台能力域、3 个技术底座、6 种页面模板

## 0.1 V10.6-R1 架构冻结记录

本版本自 2026-08-11 起作为上位架构正式冻结，进入第一刀（统一 Shell + 公共世界资料提交入口）实施。V10.5 继续作为 AI 启动、执行计划与问题库专项指令，不因 V10.6 上位化而删除或重写。

正式冻结项：

1. 4 个应用面：域主工作台、公共世界与客户协作端、平台运营后台、治理审计台。
2. 10 个中台能力域：身份与域权、项目与执行、工作流与 Agent、证据与可信、需求与连接、资产与能力包、政策与综合经营、行业态势、治理与审计、工具与连接。
3. 3 个技术底座：数据事件与平台底座、Agent 与工作流运行底座、外部连接与安全底座。
4. 6 种页面模板：工作、列表、详情/展示、配置、管理、探索画布。
5. 6 种模块状态：loading、empty、partial、blocked、error、no-permission。
6. 5 级 truth scope：verified、observed、inferred、unknown、simulation。
7. 外部动作授权：低、中、高三级授权，外加禁止级；禁止动作任何情况下不得自动执行。

V10.6 不建立与现有体系平行的路由、权限、Task、Evidence、Outcome、Realm 和数据模型；新能力优先复用现有 Realm、Project、Membership、Intake、Authorization 与 AuditLog。

## 1. 全局设计：WorkBuddy 式统一壳层

### 1.1 壳层结构

四个应用面共用同一套壳层，只替换导航范围和内容区：

```text
┌────────┬──────────────────────────────────────────────┐
│ 左导航  │ 顶部上下文：面包屑 · 命令入口 · 环境 · 用户    │
│ 240px  ├──────────────────────────────────────────────┤
│        │                                              │
│ 一级    │ 主内容区：当前工作面                          │
│ 入口    │                                              │
│        ├──────────────────────────────────────────────┤
│        │ 底部状态条：数据连接 · truth scope · 版本      │
└────────┴──────────────────────────────────────────────┘
         右侧抽屉：证据 · 连接 · 权限 · 审批
```

### 1.2 一级导航

| 入口 | 第一阶段 | 内容 |
| --- | --- | --- |
| 今日工作 | 开放 | 待办、提醒、AI建议、阻塞、风险 |
| 客户与定位 | 开放 | 资料上传、AI分析、域主确认、定位结论 |
| 项目与计划 | 开放 | 项目、阶段、步骤、任务、进度、提醒 |
| 执行与问题 | 开放 | 步骤执行、执行记录、问题库、尝试与纠偏 |
| 结果与资产 | 开放 | Evidence、Outcome、复盘、Skill候选 |
| 工具与连接 | 开放 | MCP、Codex、OpenClaw、本地工具、外部服务 |
| 政策与经营 | 隐藏 | 第二阶段开放 |
| 能力市场 | 隐藏 | 第三阶段开放 |
| 行业态势 | 隐藏 | 第四阶段开放 |
| 共同治理 | 隐藏 | 第四阶段试点开放 |

### 1.3 页面模板

固定为六种模板，不无限扩张：

| 模板 | 主要场景 | 结构 |
| --- | --- | --- |
| 工作页面 | 今日工作、单步骤执行、项目经营 | 页面头 → 状态条 → 主线模块 → 下一步 → 上下文栏 |
| 列表页面 | 项目、任务、问题、审批、能力包 | 页面头 → 筛选 → 列表 → 详情抽屉 |
| 详情/展示页面 | 企业、品牌、产品、域、案例、能力包 | 页面头 → 主体信息 → 证据与结果 → 连接动作 |
| 配置页面 | 工作流、Agent、连接、Feature Flag | 页面头 → 模块列表 → 连接状态 → 保存 |
| 管理页面 | 平台后台、治理、审计、交易运营 | 页面头 → 分区 → 审计 → 导出 |
| 探索画布 | 行业地图、关系图谱、政策影响、情景推演 | 画布主导 → 图例 → 选择详情 → 行动入口 |

探索画布是恒域世界的核心形态，不得强行塞入普通工作页面。

### 1.4 状态规范

每个模块必须有六种状态：

| 状态 | 展示 |
| --- | --- |
| loading | 骨架，不闪烁完整假数据 |
| empty | 真实空状态，说明缺什么输入 |
| partial | 部分数据，明确哪些字段缺失 |
| blocked | 阻塞原因和解除动作 |
| error | 错误信息与重试 |
| no-permission | 权限边界，不展示越权内容 |

truth scope 固定五级：

| 级别 | 含义 |
| --- | --- |
| verified | 已验证 |
| observed | 已观察 |
| inferred | AI推断 |
| unknown | 待补充 |
| simulation | 预演 |

### 1.5 设计令牌

| 类别 | 建议 |
| --- | --- |
| 主色 | 一个蓝色主色，不再使用多色渐变 |
| 中性色 | 背景、面板、边框、正文、弱化文本 |
| 语义色 | 绿=已连接/已完成，琥珀=待确认/待补充，红=错误/阻塞，紫=AI推断 |
| 圆角 | 控件 6px，容器 8px，不再使用大圆角卡片 |
| 间距 | 4/8/12/16/24 基础网格 |
| 字体 | system-ui + 中文回退，正文 14px，页面标题 20px |
| 阴影 | 仅浮层使用轻阴影，不做装饰阴影 |
| 图标 | lucide 图标库，统一 16px，图标必须在带标签的按钮内使用 |

### 1.6 外部动作分级授权

“所有外部动作必须域主确认”过于绝对，改为三级授权：

| 级别 | 处理方式 |
| --- | --- |
| 低风险 | 域主预授权后自动执行 |
| 中风险 | 每次执行前确认 |
| 高风险 | 域主或专业审核人确认 |
| 禁止动作 | 任何情况下不得自动执行 |

高风险动作至少包括：

- 对外发布；
- 发送客户消息；
- 签署合同；
- 支付和资金操作；
- 修改财税法结论；
- 修改权限；
- 将 Evidence 升级为 verified；
- 删除或公开私有数据。

## 2. 应用面细节设计

### 2.1 域主工作台

主产品，采用“对话 + 任务 + 工作面”：

```text
左侧一级导航
├── 今日工作
├── 客户与定位
├── 项目与计划
├── 执行与问题
├── 结果与资产
└── 工具与连接
```

每个页面由模块组成，域主可配置模块开关、顺序和默认状态。

#### 今日工作

| 模块 | 内容 |
| --- | --- |
| 今日主线 | 待办、提醒、AI建议、阻塞、风险 |
| 快速命令 | 上传资料、确认档案、新建项目、导出计划 |
| 最近连接 | 数据源状态、权限状态、truth scope |

#### 客户与定位

| 模块 | 内容 |
| --- | --- |
| 资料上传 | PDF/DOCX/XLSX/CSV/TXT/MD/图片 |
| 分析草稿 | 字段、来源、置信度、未知项 |
| 确认区 | 域主编辑并确认，确认后进入项目计划 |

#### 项目与计划

| 模块 | 内容 |
| --- | --- |
| 项目 | 名称、主体、目标、阶段 |
| 计划 | 阶段、步骤、任务、负责人、时间 |
| 进度 | 状态、百分比、提醒、同步 |
| 导出 | CSV、日程、复盘 |

#### 执行与问题

| 模块 | 内容 |
| --- | --- |
| 当前步骤 | 正在执行的任务和工具 |
| 执行记录 | 输入、输出、版本、引用、成本 |
| 问题库 | 原文、AI分类、尝试、纠偏、历史 |

#### 结果与资产

| 模块 | 内容 |
| --- | --- |
| Evidence | 真实证据、来源、状态 |
| Outcome | 结果、成本、进度、结论 |
| 复盘 | 项目复盘、方法沉淀 |
| Skill候选 | 域主确认后成为资产 |

#### 工具与连接

| 模块 | 内容 |
| --- | --- |
| 工具状态 | MCP、Codex、OpenClaw、本地工具 |
| 外部服务 | 日历、IM、数据库、数据供应商 |
| 本地源码 | 授权仓库、版本、运行记录 |

### 2.2 公共世界与客户协作端

客户、游客、潜在域主行为不同，不增加应用面数量，但内部划分四个路由空间：

```text
/public/*
公开行业、域、主体、案例和能力展示

/intake/*
客户资料提交、授权和补充

/client/*
项目进度、成果确认、问题反馈和交付

/market/*
能力发现、评估和获得授权
```

页面规则：

- 公开内容只展示已验证或已观察的真实结果；
- 客户资料提交需要明确授权和补充路径；
- 客户项目空间只展示与该项目相关的数据；
- 市场入口由 Feature Flag 控制，不建立无数据空壳。

### 2.3 平台运营后台

面向平台运营者：

| 页面 | 内容 |
| --- | --- |
| 平台总览 | 域、项目、数据源、接口状态 |
| 域管理 | Realm、Entity、Membership |
| 数据源 | 来源、连接、覆盖率、未知区 |
| Feature Flag | 四阶段开关，不开放空壳页面 |
| 接口监控 | API、Agent、工具执行状态 |
| 系统配置 | 模型、额度、安全、备份 |

### 2.4 治理审计台

面向治理与审计：

| 页面 | 内容 |
| --- | --- |
| 权限策略 | 角色、成员、数据边界 |
| 审批中心 | 项目、计划、发布、外部动作 |
| 审计日志 | 事件、操作、变更、回滚 |
| 风险控制 | 权限、成本、外部工具、未验证数据 |
| 共同治理 | 后续阶段试点开放 |

### 2.5 能力市场职责分工

能力市场不重复建设四套页面，职责固定到应用面、中台和底座：

| 角色 | 职责 |
| --- | --- |
| 域主工作台 | 创建、封装、定价、发布和管理能力包 |

| 平台运营后台 | 上架、订单和交易运营 |
| 治理审计台 | 证据、权属、侵权和争议 |
| 资产与能力包中台 | 版本和授权 |
| 需求与连接中台 | 匹配 |
| 外部连接与安全底座 | 安装和执行 |

## 3. 中台能力域细节

中台不是独立页面，而是统一 API 与领域模型。

### 3.1 身份与域权中台

- 定位：Realm、Entity、成员和权限的唯一真相源。
- 核心实体：Realm、Entity、Membership、Role。
- 主要 API：realm、entity、membership、permission。
- 边界：前端不自行判断身份，所有权限判断走后端。

### 3.2 项目与执行中台

- 定位：项目、计划、任务、进度、提醒。
- 核心实体：Project、Work Item、Reminder、Progress。
- 主要 API：project、plan、task、reminder。
- 边界：不建立第二套 Task 体系。

### 3.3 工作流与 Agent 中台

- 定位：域主工作流、Agent 配置、工具执行。
- 核心实体：Workflow、AgentConfig、Tool、Execution。
- 主要 API：workflow、agent、tool、execution。
- 边界：工作流归域主，平台负责运行、版本和审计。

### 3.4 证据与可信中台

- 定位：Evidence、Claim、Outcome、信誉。
- 核心实体：Evidence、EvidenceClaim、Outcome、Reputation。
- 主要 API：evidence、claim、outcome、trust。
- 边界：observed 不得显示为 verified，completed 不自动提高信誉。

### 3.5 需求与连接中台

- 定位：真实需求、连接候选、合作记录。
- 核心实体：Demand Event、Connection Candidate、Engagement。
- 主要 API：demand、connection、engagement。
- 边界：候选必须带理由、证据、风险和未知项。

### 3.6 资产与能力包中台

- 定位：SOP、Skill、Method、能力包和授权。
- 核心实体：SOP、Skill、CapabilityPackage、License。
- 主要 API：sop、skill、capability、license。
- 边界：模板只能来自真实有效方法，需域主确认。

### 3.7 政策与综合经营中台

- 定位：政策、地区、财务、税务、法务、合同、资质、现金流、组织和经营风险。
- 核心实体：PolicySource、PolicyEvent、Jurisdiction、FinancialSnapshot。
- 预留实体：TaxProfile、LegalRequirement、LicenseRequirement、ContractRecord、CashflowSnapshot、Receivable、Payable、Budget、ProfessionalReview、BusinessRisk。
- 主要 API：policy、jurisdiction、financial、tax、legal、contract、cashflow、risk。
- 边界：高风险的财税法决策必须专业审核人确认，AI 只辅助。

### 3.8 行业态势中台

- 定位：World State、行业事件、信号和缺口。
- 核心实体：World Contract、World State Snapshot、IndustryEvent、Signal。
- 主要 API：world、snapshot、event、signal。
- 边界：推断必须标记，未知区必须显示缺口。

### 3.9 治理与审计中台

- 定位：事件、审计、审批、共同治理。
- 核心实体：Event Backbone、AuditLog、Approval、GovernanceProposal。
- 主要 API：event、audit、approval、governance。
- 边界：所有外部动作和权限变更留痕。

### 3.10 工具与连接中台

- 定位：MCP、Adapter、外部平台连接。
- 核心实体：Connector、MCP Server、Adapter、CredentialPolicy。
- 主要 API：connector、mcp、adapter。
- 边界：外部平台不得成为不可替换核心，密钥不进入前端。

## 5. 数据真实性与权限规则

1. AI 提取默认标记为 draft、observed 或 inferred。
2. 未知字段标记为 unknown，不得补造。
3. simulation 不得写入生产关系。
4. 前端不得直接修改 Reputation。
5. 外部动作按低、中、高三级授权执行，禁止动作永不自动执行。
6. 不建立第二套 Realm、Evidence、Demand、Connection 或 Outcome。
7. 未批准不新增数据库模型和迁移。

## 7. 组件与交互规范

### 核心组件

| 组件 | 规则 |
| --- | --- |
| Shell | 四个应用面共用一套壳层 |
| NavRail | 一级入口固定，Feature Flag 控制显示 |
| ContextBar | 面包屑、命令、环境、用户 |
| Module | 页面最小可配置单元 |
| StatusStrip | 数据连接、truth scope、版本 |
| Drawer | 证据、连接、权限、审批 |
| DataSourceBadge | 已连接/待配置/缺失 |
| TruthBadge | verified/observed/inferred/unknown/simulation |
| CommandPalette | 全局搜索与命令 |
| ApprovalItem | 待确认、来源、风险、确认动作 |

### 交互规则

- 页面模块支持配置：开关、排序、默认状态。
- 外部动作按风险等级执行：低风险预授权、中风险确认、高风险人工审核、禁止动作永不执行。
- 所有列表支持空、部分、阻塞、错误和权限状态。
- 所有导出只导出当前页面可见的真实数据。
- 键盘可达，图标按钮必须有 aria-label。

## 8. 实施顺序建议

今日工作应在真实业务模块能够产生任务、提醒和阻塞后再聚合，避免先做成假数据看板。

1. 设计令牌和统一 Shell。
2. 域主工作台壳层。
3. 公共世界与客户协作端的资料提交。
4. 客户与定位。
5. 项目与计划。
6. 执行与问题。
7. 结果与资产。
8. 工具与连接。
9. 今日工作聚合。
10. 平台运营后台。
11. 治理审计台。

## 9. 验收标准
