## 1. P0-0：让指令真正加载

### 1.1 新增：仓库根 `D:\GEO-Industry-Engine\AGENTS.md`

Codex 自动发现的是仓库根/工作目录路径上的 `AGENTS.md`。根级文件保持简短（约 5～8KB），只放必须始终生效的规则和指向详细文件的路径。

建议内容（10 条硬原则）：

1. **Node Demand First**：真实节点需求与需求证据优先；架构约束实现方式，不否决已被证据证明的需求。
2. **真实性与证据分级**：真实证据 / 公开研究 / 内部推测 / 模拟数据，四档分级。
3. **模拟数据隔离**：不得把模拟数据、演示数据当真实数据使用或展示。
4. **风险分级流程**：按任务风险选择 L0～L3 通道，不统一走重流程。
5. **复用优先**：新建文件/模块前先检查现有实现与 `.codex/REFERENCES.md`。
6. **范围匹配测试**：修改后运行与改动范围匹配的测试，未跑测试不得声称完成。
7. **不自动修改长期规则**：任务发现写入 LESSONS 候选区；只有重复出现或高风险事故，经人工/CTO 评审 + ADR 后才允许提升为长期规则。
8. **Git 操作走 `scripts/sync.ps1`**：提交与推送统一入口。
9. **不触碰无关脏文件**：如 `frontend `（带尾随空格目录）、`tmp_*.py`、日志文件，不主动清理。
10. **角色与详细规则按需读取**：入口指向 `.codex/README.md`，不全部强制加载。

### 1.2 移动：`.codex\AGENTS.md` → `.codex\runtime.md`

- 修改头部说明：删除"每次对话自动加载"的断言，改为"本文件为运行时参考，实际加载入口是仓库根 AGENTS.md"。

## 2. P0-1：Node Demand First 提升为最高原则

### 2.1 `roles/cto_架构师.md`（原 `agents/cto_架构师.md`）

- 真相源顺序改为：

```
真实节点需求与需求证据
→ 项目使命和安全边界
→ 领域事实与数据真实性
→ 架构约束
→ 产品系统归属
→ 技术实现
```

- 修改决策树："不属于现有系统 → 直接驳回"改为"需求证据成立但现有系统容纳不了 → 触发架构评审，由用户/CTO 决策是否扩展系统边界"。
- 商业判断改为四层价值：
  1. 节点必要性（高频、高损失、不得不解决）
  2. 需求证据强度（行为/咨询/付费/结果数据）
  3. 基础设施复用度（是否被多个节点重复需要）
  4. 经济邻近度（收入/降本/降险）
  5. 明确：收入邻近度不得凌驾于需求真实性。
- 删除"知识图谱就是护城河"表述；护城河只可能来自持续更新、来源可验证、节点纠错、与真实结果关联、难以公开复制的数据。

### 2.2 `roles/pm_产品经理.md`

- 新增"需求证据门"，每份需求单必须包含：

```yaml
target_node: 目标节点
job_to_be_done: 节点要完成的真实任务
demand_source: 访谈/咨询记录/行为数据/公开研究/投诉
observed_count: 已观察次数
current_workaround: 当前如何解决
current_cost: 时间/人工/金钱/风险
frequency: 发生频率
economic_impact: 经济或决策影响
adoption_cost: 学习和操作成本
success_metric: 如何证明功能有价值
kill_condition: 什么结果出现时停止开发
```

- 证据分级规则：
  - 有真实证据 → 进入功能优先级评估
  - 只有公开研究 → 进入实验
  - 只有内部推测 → 进入假设池
  - 没有证据 → 不得定为 P0
- 修改"无法匹配五大系统 → 驳回"为"证据成立则触发产品/架构评审，不直接驳回"。

## 4. P0-3：L0～L3 风险通道 + R-002 修正

### 4.1 新增 `.codex\workflows\risk_channels.md`

| 通道 | 适用任务 | 流程 |
|------|---------|------|
| L0 快速修复 | 拼写、编码、lint、小 bug | 检查 → 修改 → 定向测试 → 摘要 |
| L1 普通功能 | 不改变领域模型 | 需求门 → 复用检查 → 实现 → 测试 |
| L2 架构变更 | 表、实体、权限、公共 API、评分语义 | PM 证据 → CTO → ADR → 实现 → 完整验证 |
| L3 战略决策 | 定位、新节点、新行业、重大路线 | 只研究并提出方案，不直接编码 |

### 4.2 `feature_development.md`

- 改为引用风险通道，作为 L1 详细流程保留；不再要求所有任务都走 8 步。

### 4.3 `ambiguity_handling.md`（R-002）

- 触发条件改为：只有不同解释会导致明显不同、不可逆或高成本结果时才询问。
- 可逆、低风险任务允许声明假设后继续，与自主执行一致。

### 4.4 `protocol.md`

- 六段式只用于：
  - 真正启用独立子 Agent / 独立上下文
  - 跨 3 个以上模块
  - 数据模型或架构变更
  - 高风险发布任务
- 普通修复、单模块任务不强制六段式。
- 同步修复章节顺序（零、复用检查应放在一、之前）与旧角色名引用。
