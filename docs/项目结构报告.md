## 一、顶层目录结构

```
GEO-IE/
├── docs/             项目文档（38 份，中文命名）
├── backend/          后端（FastAPI，Python 3.12）
├── frontend/         前端（Next.js，TypeScript）
├── agents/           智能 Agent 系统（Python）
├── config/           配置中心（评分权重 YAML）
├── tests/            测试（pytest）
├── scripts/          工具脚本
├── database/         数据库相关
├── infrastructure/   基础设施（Docker）
├── .codex/           Codex 开发辅助配置
└── README.md
```

## 二、文件命名规则

### 核心文档（docs/）

| 规则 | 说明 | 示例 |
|------|------|------|
| 编号前缀 | 两位数字，00-99，支持分组 | `00_`, `01_`, ... |
| 中文标题 | 标题使用中文表达 | `项目宪章`, `技术架构` |
| 技术术语 | API/Agent/GEO/Context/MCP 等保留英文 | `Agent_OS设计`, `API接口规范` |
| 分隔符 | 编号与标题之间用下划线 | `00_项目宪章.md` |
| 扩展名 | 统一使用 `.md` | — |
| 支持文件 | 非编号文档也使用中文命名 | `索引.md`, `架构变更流程.md` |

### 代码目录（backend/、agents/ 等）

代码目录保留英文，因为：
- Docker 配置、Python 导入路径、pytest 发现机制硬编码引用英文路径
- 中文技术公司的行业惯例

### 命名禁区

- ✗ 不出现纯英文文档名（如 `README.md` 除外）
- ✗ 不出现空格
- ✗ 不出现特殊字符（`@`, `#`, `%` 等）

## 五、新增文档规则

1. **编号**：在对应分组中取下一个可用编号
2. **命名**：`{编号}_{中文标题}.md`，技术术语保留英文
3. **权威等级**：新文档默认为 Secondary，经 CTO 评审后升级
4. **元数据**：每个文件顶部必须有 YAML 前注（status / authority / version / last_review）
5. **注册**：更新 `索引.md` 和 `.codex/REFERENCES.md`
