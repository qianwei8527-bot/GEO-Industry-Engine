## 1. 连接注册表

代码位置：`frontend/src/lib/code-connection.ts`

每个连接包含：

```text
应用面 / 页面 / 路由 / 权限 / 组件 / API / 状态
```

状态：

- implemented：页面和核心 API 已接通；
- partial：页面存在，部分接口待接通；
- reserved：只冻结路由和 Feature Flag，不建空壳。

## 3. 系统连接页面

路由：`/system-map`

组件：`frontend/src/components/system-map/system-map-page.tsx`

该页面读取 `code-connection.ts`，展示所有页面的路由、组件、API 和状态，后续新增页面只需在注册表登记。

## 3.1 模拟闭环连接

为验证基础架构链路，新增模拟闭环：

- API：`POST /api/v1/simulation/loops/run`、`GET /api/v1/simulation/loops/latest`
- 组件：`frontend/src/components/realm-owner/simulation-loop-panel.tsx`
- 链路：模拟客户资料 → 本地结构化提取 → 模拟定位结论 → 模拟项目 → 模拟执行计划
- 隔离：所有记录标记 `simulation`，Evidence 使用 `synthetic`，项目与计划使用 `synthetic`，`may_affect_real_metrics=False`，不写入真实关系或 Reputation。

## 3.2 R2 客户与定位连接

- 路由：`/realm/{realm_id}/customers`
- 组件：`frontend/src/components/realm-owner/client-positioning-workbench.tsx`
- API：`/intakes/{id}/workbench`、`/profile`、`/profile/confirm`、`/supplement`、`/positioning/generate`、`/positioning/confirm`、`/project`
- 状态机：待审核 → 审核中 → 待补充 → 档案已确认 → 定位草稿 → 定位已确认 → 项目已创建
- 版本：复用 `IntakeAnalysis.version` 保存档案与定位历史，不新增模型。
- 项目：复用 `GeoProject.metadata_json` 关联 Intake、档案版本、定位版本和 config hash；重复触发只返回已有项目。

## 5. 验收标准

- 每个页面在注册表中有连接记录；
- implemented 页面必须有真实路由和真实 API；
- partial 页面必须明确缺失接口；
- reserved 页面不建空壳；
- 新增页面先登记，再开发。
