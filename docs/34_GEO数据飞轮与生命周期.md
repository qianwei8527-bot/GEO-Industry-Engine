# GEO数据飞轮与生命周期

> 系统如何自我增强？——GEO-Industry-Engine形成长期网络效应的核心机制。

---

## 一、核心问题：系统如何自我增强？

基础设施不是因为功能多而成立，而是因为**越用越聪明**。

GEO不是一个内容平台，不是一个数据库，不是一个工具集合。它的最终价值在于：

**让全球产业数据、关系、能力、信任不断积累，并反过来提升AI理解产业世界的能力。**

## 二、三层核心飞轮

聚焦于尚无现有文档覆盖的飞轮机制。已有飞轮层（信任→32，贡献→31，Agent→04+33）不再重复。

### 飞轮1：产业数据飞轮

GEO最基础的飞轮，驱动所有其他飞轮运转。

```text
更多产业参与者（企业/个人/机构）加入
            |
            v
    更多企业/人才/产品数据
            |
            v
      产业图谱更完整
            |
            v
     AI理解更准确
            |
            v
       推荐更有效
            |
            v
     更多参与者加入
```

| 阶段 | 触发条件 | 输出 | 关联文档 |
|------|---------|------|---------|
| 冷启动 | 种子数据+定向邀请 | 初始产业图谱 | 20_数据生产机制与初始化策略.md |
| 增长期 | 推荐价值驱动 | 数据量指数增长 | 15_竞争情报与增长实验模型.md |
| 成熟期 | 生态自驱动 | 持续数据流入 | 31_GEO贡献者与开发者生态.md |

### 飞轮2：关系网络飞轮

数据只是起点。真正不可替代的是**关系**——企业之间、能力之间、人才之间如何连接。

```text
         更多实体连接
            |
            v
      更准确的产业关系
            |
            v
      更高的匹配效率
            |
            v
     更多有意义的连接产生
```

关键机制：**关系强度计算**——不是简单记录"有关/无关"，而是计算频率、时间、影响范围、可信度、结果反馈的综合权重。

这条飞轮与 `26_GEO产业内核与开放协议.md` 的 Relationship Engine 直接衔接。

### 飞轮3：AI推荐飞轮

这是GEO区别于传统产业地图的核心飞轮。

```text
      用户需求/意图
            |
            v
     GEO理解意图
            |
            v
      匹配产业能力
            |
            v
       推荐结果
            |
            v
       用户反馈
            |
            v
       模型优化
```

示例：
```
用户："找一家帮助传统制造企业做AI升级的团队。"
系统推荐A公司 → 用户选择A → 合作有效 → 系统学习：
   A公司的制造AI能力权重提升，同类推荐更精准
```

这条飞轮与 `33_GEO产业上下文层.md` 的 Context Engine（特别是Intent Context和Decision Context）直接衔接，是数据反馈进入智能层的通道。

## 四、数据生命周期（Data Lifecycle）

数据不是静态资产，需要从生到死的管理。

### 5个阶段

```text
发现 → 验证 → 结构化 → 应用 → 反馈 →（循环）
```

| 阶段 | 内容 | 负责方 | 关联文档 |
|------|------|-------|---------|
| **发现** | 企业提交、网络采集、Agent发现 | Scanner Agent + 社区 | 20_数据生产机制与初始化策略.md |
| **验证** | 企业认证、第三方验证、用户反馈、AI交叉验证 | 认证系统 + 验证Agent | 10_数据更新与认证机制.md, 22_GEO测量方法论.md |
| **结构化** | 文本 → 实体 → 关系 → 知识图谱 | Entity Engine + Capability Engine | 02_领域模型设计.md, 25_GEO产业本体模型.md |
| **应用** | 推荐、搜索、分析、Agent调用 | Context Engine + 各决策模型 | 33_GEO产业上下文层.md |
| **反馈** | 结果评估、准确率、价值判断 | 各Agent + 用户 | 本文件第六章（负反馈机制） |

### 生命周期管理原则

1. **每阶段可追溯**：一条数据在任何阶段都可以查到它在生命周期中的位置和状态
2. **阶段失活机制**：不再被引用的数据自动降级，降低图谱噪声
3. **数据老化策略**：超过特定时间未经验证的数据，可信等级自动下降

## 五、数据血缘与可信链（Data Provenance）

GEO中每条数据都应知道"从哪来、谁证明、可信等级是什么"。

### 逐级溯源模型

```text
能力声明："某公司具备AI营销能力"

 来源链：
 ├── 企业自述（Level 0）
 │    └── 来源：企业提交
 ├── 案例证明（Level 2）
 │    └── 来源：3个已交付客户案例
 ├── 第三方验证（Level 3）
 │    └── 来源：行业报告引用 + 客户实名评价
 └── 市场验证（Level 4）
      └── 来源：持续AI推荐表现 + 用户反馈统计
```

### 数据血缘的记录结构

每条数据记录附带 `provenance` 字段：

```json
{
  "data_id": "CAP-000001",
  "value": "AI营销能力",
  "provenance": {
    "source": "enterprise_submission",
    "confidence_level": 3,
    "evidence_chain": [
      {"source": "企业提交", "date": "2026-01-15", "verifier": "企业认证L1"},
      {"source": "客户案例", "count": 3, "verifier": "案例审核"},
      {"source": "行业报告", "report_id": "GARTNER-2026-01", "verifier": "AI提取"}
    ],
    "last_verified": "2026-06-01",
    "expiry_date": "2027-06-01"
  }
}
```

与 `22_GEO测量方法论.md` 的"数据来源等级"一致，在此扩展为完整的血缘追踪体系。

## 六、负反馈机制

多数平台只收集**正反馈**（什么有效）。基础设施还必须知道**哪里错了**。

### 负反馈的来源

| 来源 | 示例 | 处理方式 |
|------|------|---------|
| 错误推荐 | 推荐了不适合的企业 | 记录三元组（用户, 需求, 不符合的企业） |
| 过时信息 | 企业已转型但图谱未更新 | 标记数据老化，触发重新验证 |
| 冲突信息 | 多个来源对同一企业描述不一致 | 进入冲突仲裁流程 |
| 用户负面评价 | 合作评价低 | 关联到对应企业/能力，下调可信权重 |

### 负反馈闭环

```text
   AI推荐/决策
       |
       v
    用户/Agent 反馈（含负反馈）
       |
       v
   原因分析（为什么错？）
       |
       v
   模型/图谱调整
       |
       v
   未来优化（同类错误避免）
```

### 与现有系统的关系

| 现有组件 | 负反馈的输入 |
|---------|------------|
| 16_GEO评分算法 | 错误推荐影响评分因子 |
| 22_GEO测量方法论 | 增加负反馈作为测量维度 |
| 33_Context Layer | Decision Context增加"风险因素"维度 |
| 32_标准体系 | 负反馈影响信任指数 |

## 七、数据资产分层

GEO数据不混在一起管理。按价值递增分4层：

| 层 | 内容 | 访问权限 | 价值特征 |
|----|------|---------|---------|
| **Layer 1：公共产业数据** | 行业、企业基础信息、分类 | 开放 | 基础设施，降低参与门槛 |
| **Layer 2：生态关系数据** | 合作关系、能力关系、人才关系 | 注册用户 | 核心资产，网络效应载体 |
| **Layer 3：行为数据** | 搜索需求、匹配结果、用户选择 | 高级用户+AI | 高价值，理解产业需求流 |
| **Layer 4：智能数据** | AI判断、趋势预测、决策模型 | 平台+认证伙伴 | 最高价值，持续累积的产业智能 |

```text
       价值递增
          ^
          |
  Layer 4: 智能数据   ← AI判断、预测、决策
  Layer 3: 行为数据   ← 搜索、匹配、选择
  Layer 2: 关系数据   ← 合作、能力、人才关系
  Layer 1: 公共数据   ← 行业、企业基础信息
          |
          v
       规模递增
```

与 `03_数据架构.md` 的数据湖设计衔接——所有4层存储在统一数据架构中，通过访问控制区分层级。

## 八、产业意图数据：飞轮的终极燃料

### 为什么意图是最贵资产

| 平台 | 核心意图数据 | 价值 |
|------|------------|------|
| Google | 搜索意图 | 广告匹配 |
| Amazon | 购买意图 | 商品推荐 |
| LinkedIn | 职业意图 | 招聘匹配 |
| **GEO** | **产业发展意图** | **产业决策+机会发现** |

### GEO累积的意图数据类型

| 意图类型 | 来源 | 反映什么 |
|---------|------|---------|
| 企业进入意图 | 企业搜索"如何进入XX行业" | 产业资本流向 |
| 能力寻找意图 | "寻找XX能力的供应商" | 产业需求热点 |
| 人才发展意图 | "如何进入GEO行业" | 人才供给趋势 |
| 投资意图 | "XX赛道值得投吗" | 资本关注方向 |
| 政府规划意图 | "如何发展XX产业" | 政策优先领域 |

### 意图作为飞轮燃料

```
用户需求/搜索
      |
      v
   意图数据
      |
      v
  产业趋势洞察  →  更好匹配  →  更高价值  →  更多用户 →  更多意图数据
```

这三层核心飞轮 + 数据生命周期管理 + 数据血缘 + 负反馈 + 资产分层 + 意图数据，共同构成GEO的自我增强闭环。飞轮一旦启动，后来者无法通过复制功能来替代，因为关系网络、信任积累和意图数据需要时间。
