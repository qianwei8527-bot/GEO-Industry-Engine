# 数据生产机制与初始化策略

> 50+张表的数据从哪里来？第一桶数据怎么填？数据如何保鲜？

---

## 一、数据生产总览

### 1.1 四种生产方式

| 方式 | 占比 | 示例 | 特点 |
|------|------|------|------|
| 自动采集(爬虫/API) | 60% | AI模型数据、企业信息、新闻 | 持续运行、量大 |
| 用户提交 | 15% | 企业注册、认证申请、评论 | 需要激励、质量参差 |
| 平台计算生成 | 20% | GEO评分、排名、竞争分析 | 依赖其他数据、定时 |
| 第三方导入 | 5% | 行业报告、权威数据源 | 一次性或按需 |

### 1.2 数据流向

```
外部数据源
    ↓ (自动采集/API/爬虫)
原始数据层 (PostgreSQL raw tables)
    ↓ (数据清洗/标准化)
标准数据层 (PostgreSQL clean tables)
    ↓ (聚合/计算)
分析数据层 (GEO评分/排名/洞察)
    ↓ (同步)
展示数据层 (Redis cache / ES index)
```

## 二、自动采集管道（占60%）

### 2.1 AI模型数据管道

| 数据表 | 采集方式 | 频率 | 来源 |
|--------|---------|------|------|
| ai_models | 扫描AI社区+HuggingFace+新闻API | 每周 | HuggingFace API + Google News |
| ai_model_metrics | 公开报告+SimilarWeb法估算 | 每月 | Gartner报告+公开数据 |
| ai_model_behavior_patterns | 向各模型发送标准Prompt | 每天 | AI模型API/网页 |
| ai_model_industry_scores | 分析查询结果中的行业分布 | 每天 | 自建分析引擎 |
| ai_model_sources | 提取查询结果中的引用来源 | 每天 | 模型回答解析 |
| ai_query_results | 批量查询引擎 | 每天 | AI模型API/网页 |

**模型查询引擎设计**：

```
查询任务队列(Redis Queue)
    ↓
并行向各模型发送Prompt
    ↓ (超时15秒)
解析回答内容
    ↓
提取提及企业 + 引用来源 + 情感
    ↓
写入 ai_query_results
    ↓
触发 ai_model_industry_scores 更新
```

### 2.2 企业数据管道

| 数据表 | 采集方式 | 频率 | 来源 |
|--------|---------|------|------|
| companies | 百度百科+天眼查+官网爬虫 | 首次全量+每周增量 | 公开API+爬虫 |
| company_geo_scores | 计算引擎 | 触发式 | 自建计算 |
| company_ai_mentions | 从ai_query_results提取 | 每天 | 自建提取 |

**企业数据初始化**：第一批100家企业从百度百科"中国500强"+"行业领军企业"条目中提取。

### 2.3 行业与趋势数据管道

| 数据表 | 采集方式 | 频率 | 来源 |
|--------|---------|------|------|
| industries | 国家行业标准+专家定义 | 一次性+季度审核 | GB/T 4754标准 |
| industry_metrics | 公开统计+计算 | 每月 | 统计局+行业协会 |
| geo_industry_trends | 行业报告+RSS+新闻分析 | 每周 | Gartner/McKinsey + RSS |
| information_sources | 预定义+用户提交 | 一次性+持续 | 专家定义+社区 |

### 2.4 Prompt与查询数据管道

| 数据表 | 采集方式 | 频率 | 来源 |
|--------|---------|------|------|
| prompt_knowledge_base | 从ai_query_results提取+分类 | 每天 | 自建查询引擎 |
| intent_prompts | 意图分类引擎 | 每天 | LLM分类 |

## 三、用户提交机制（占15%）

### 3.1 企业注册流程

```
用户提交企业名称+网址
    ↓
爬虫自动补充企业信息(百科/官网)
    ↓
管理员审核(或AI自动审核)
    ↓
写入 companies 表
    ↓
触发 GEO 评分计算
```

### 3.2 认证申请流程

```
用户提交认证材料
    ↓
AI初审(材料完整性)
    ↓
人工复审(L3-L4)
    ↓
写入 certifications
    ↓
更新企业认证等级
```

### 3.3 社区贡献机制

```
用户提交: 产业数据纠错/工具推荐/案例分享
    ↓
AI审核(重复检测+格式校验)
    ↓
社区投票(>3票有效)
    ↓
管理员确认
    ↓
写入对应数据表
    ↓
贡献者获得积分
```

## 四、平台计算生成（占20%）

### 4.1 GEO评分计算引擎

```
触发器: 企业数据更新/模型行为更新/新查询结果
    ↓
读取9项因子数据
    ↓
加权计算 GEO_Score = E x 0.15 + T x 0.15 + C x 0.12 + S x 0.12 + ...
    ↓
更新 company_geo_scores
    ↓
更新 ai_brand_rankings
    ↓
检查是否触发告警(评分变化>5分)
```

### 4.2 品牌排名生成

```
从 company_geo_scores 读取全量评分
    ↓
按行业分组排序
    ↓
计算排名变化
    ↓
写入 ai_brand_rankings
    ↓
标记排名上升/下降/新入榜
```

### 4.3 竞争分析生成

```
读取竞争企业对的GEO评分
    ↓
计算各维度差距
    ↓
识别优势/劣势领域
    ↓
写入 visibility_gaps
    ↓
生成对比报告
```

### 4.4 商机发现引擎

```
读取 prompt_knowledge_base
    ↓
识别高频查询+低竞品占位
    ↓
计算商业价值评分
    ↓
写入 ai_opportunities
    ↓
推送到交易市场
```

## 五、数据初始化策略（第一桶数据）

### 5.1 第一批数据来源

| 数据 | 数量 | 来源 | 时间 |
|------|------|------|------|
| AI模型 | 20+ | ChatGPT/Gemini/Claude/DeepSeek等主流模型 | Day 1 |
| 企业 | 100+ | 百度百科"中国企业500强"+各行业领军企业 | Day 1-3 |
| 行业 | 50+ | GB/T 4754产业分类标准 | Day 1 |
| 模型行为 | 1000+ | 向各模型发送100+标准Prompt | Day 1-2 |
| 查询结果 | 5000+ | 100 Prompt x 5模型 x 10次 | Day 1-3 |
| GEO评分 | 100+ | 基于初始化数据计算 | Day 3 |

### 5.2 初始化脚本流程

```python
# 伪代码：数据初始化管道
def initialize_data():
    # 1. 加载行业分类
    industries = load_industry_standards()
    bulk_insert('industries', industries)
    
    # 2. 加载AI模型库
    models = scan_known_ai_models()
    bulk_insert('ai_models', models)
    
    # 3. 加载100家初始企业
    companies = scrape_top_companies()
    bulk_insert('companies', companies)
    
    # 4. 发送批量查询
    prompts = load_industry_prompts()
    for model in models:
        for prompt in prompts:
            result = query_ai_model(model, prompt)
            insert_query_result(result)
    
    # 5. 计算初始GEO评分
    calculate_all_geo_scores()
    
    # 6. 生成初始排名
    generate_rankings()
```

## 九、成本控制策略

### 9.1 LLM API成本控制

| 策略 | 说明 | 预估节省 |
|------|------|---------|
| 分层采样 | 重点企业每天扫，普通企业每周扫 | 60% |
| 缓存复用 | 相同行业+相同Prompt 24h内复用 | 30% |
| 混合调度 | 先用免费额度，超出后降频 | 20% |
| 模拟基线 | API预算不足时用历史数据推演 | 100%替代 |

### 9.2 缓存规则

| 缓存类型 | 有效期 | 失效条件 |
|---------|--------|---------|
| 模型查询结果 | 4小时 | 有新数据到达 |
| GEO评分 | 1小时 | 新查询结果更新 |
| 企业信息 | 24小时 | 企业主动更新 |

| 质量维度 | 监控方式 | 修复机制 |
|---------|---------|---------|
| 完整性 | 定时检查必填字段 | 自动重新采集 |
| 准确性 | 交叉验证多数据源 | 置信度评分<0.6的标记待审 |
| 时效性 | 超时检查 | 超过更新周期2倍的发告警 |
| 一致性 | 跨表关联校验 | 不一致数据标记并重新计算 |

## 数据生命周期与血缘

贡献数据不仅是"输入数据"，还涉及数据的完整生命周期管理。详见 [32_GEO数据飞轮与生命周期.md](32_GEO数据飞轮与生命周期.md) 第四至五章。

| 生命周期阶段 | 在本机制中的体现 |
|------------|----------------|
| 发现 | 企业提交/网络采集/Agent发现(本章) |
| 验证 | 企业认证/第三方验证(10_数据更新与认证机制.md) |
| 结构化 | 实体识别→关系发现(02_领域模型设计.md) |
| 应用 | 推荐/搜索/Agent调用(33_Context Layer) |
| 反馈 | 负反馈机制(22_测量方法论) |

每条数据附带 `provenance` 字段记录来源链、可信等级和过期时间，与认证机制配合形成完整数据可信体系。
