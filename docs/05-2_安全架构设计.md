## 一、安全架构总览

```
+----------------------------------------------+
|                安全治理层                       |
|  安全策略 | 合规审计 | 风险管理 | 事件响应       |

|                应用安全层                       |
|  认证 (JWT+OAuth2) | 授权 (RBAC) | 输入验证   |

|                数据安全层                       |
|  传输加密 (TLS 1.3) | 静态加密 (AES-256)      |

|                基础设施安全层                    |
|  网络隔离 | 防火墙 | WAF | DDoS防护 | 容器安全  |
+----------------------------------------------+
```

## 二、认证体系

### 2.1 认证策略

| 方式 | 用途 | 有效期 | 实现文件 |
|------|------|--------|---------|
| JWT Access Token | API认证 | 15分钟 | core/security.py |
| JWT Refresh Token | Token续期 | 7天 | api/v1/auth.py |
| API Key | MCP/外部系统 | 永久(可吊销) | api/v1/mcp_router.py |
| OAuth2 (预留) | 第三方登录 | -- | 接口预留 |

### 2.2 JWT载荷结构

```json
{
  "sub": "user-uuid",
  "role": "enterprise_admin",
  "tenant": "tenant-uuid",
  "org": "org-uuid",
  "permissions": ["read:assessment", "write:company", "apply:certification"],
  "exp": 1680000000,
  "iat": 1679999100
}
```

### 2.3 认证流程

用户登录 -> POST /auth/login -> 验证凭证 (bcrypt) -> 签发 Access Token + Refresh Token -> 后续请求带 Authorization: Bearer token -> 过期后 POST /auth/refresh 续期

## 三、授权体系 (RBAC)

### 3.1 角色定义

| 角色 | 权限范围 | 典型用户 |
|------|---------|---------|
| platform_admin | 全部 | 平台管理员 |
| audit_admin | 认证审核 + 只读配置 | 认证审核员 |
| config_admin | 配置管理 | 配置管理员 |
| enterprise_admin | 本企业全部数据 | 企业管理员 |
| enterprise_member | 本企业只读 | 企业成员 |
| individual | 个人数据 | 个人用户 |
| provider | 服务商数据 | 服务商 |
| read_only_ops | 聚合数据只读 | 运营查看 |
| anonymous | 公开数据 | 未登录用户 |

### 3.2 权限矩阵 (数据范围)

| 角色 | 可见范围 | 可操作 | 数据导出 |
|------|----------|:----:|:------:|
| platform_admin | 全部 | CRUD | 是 |
| audit_admin | 全部(只读) + 认证审核 | 审核 | 否 |
| enterprise_admin | 本企业 | CRUD | 是(本企业) |
| enterprise_member | 本企业 | 只读 | 否 |
| individual | 个人 | CRUD | 是(个人) |
| provider | 服务+客户授权 | CRUD | 是(授权) |
| anonymous | 公开评估+首页 | 搜索 | 否 |

### 3.3 实现方式

- 代码: backend/app/api/deps.py (依赖注入)
- 配置: config/pricing/permissions.yaml
- 中间件: 每个API端点通过 Depends(get_current_user) 强制认证

## 四、数据安全

### 4.1 传输安全

- 全站 HTTPS (TLS 1.3 minimum)
- API Endpoint 强制 HTTPS
- WebSocket 使用 WSS
- HSTS 头: max-age=31536000; includeSubDomains

### 4.2 静态数据保护

| 数据类型 | 加密方式 | 密钥管理 |
|---------|---------|---------|
| 用户密码 | bcrypt (cost=12) | -- |
| API Key | SHA-256 hash | -- |
| PII数据 | AES-256-GCM | 环境变量/密钥管理服务 |
| 数据库备份 | AES-256 | 独立备份密钥 |
| JWT签名 | RS256 | 私钥/公钥对 |

### 4.3 数据隔离

- 多租户: 所有查询必须带 tenant_id
- ORM 查询强制 filter: query.filter(Model.tenant_id == current_tenant_id)
- 数据库级: 可选 PostgreSQL Row Level Security

### 4.4 数据脱敏

对外输出时自动脱敏:
- 手机号: 138****1234
- 邮箱: zh***@example.com
- 身份证: 前6后4

## 五、API安全

### 5.1 速率限制

| 端点类别 | 限制 | 窗口 |
|---------|------|------|
| 公开API | 100 req/min | 1分钟 |
| 认证API | 10 req/min | 1分钟 (防暴力) |
| 企业API | 300 req/min | 1分钟 |
| MCP API | 1000 req/min | 1分钟 |

### 5.2 输入验证

- 所有输入通过 Pydantic Schema 验证
- SQL注入: 使用ORM参数化查询
- XSS: 前端输出转义 + CSP头
- 文件上传: 大小限制(10MB) + 类型白名单

### 5.3 安全响应头

- Content-Security-Policy: default-src 'self'
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY
- X-XSS-Protection: 1; mode=block
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: camera=(), microphone=(), geolocation=()

## 六、审计与合规

### 6.1 审计日志

所有关键操作记录: 操作者(user_id) + 操作类型(CREATE/READ/UPDATE/DELETE/EXPORT) + 资源(entity_id/table) + 时间戳 + IP地址 + User-Agent + old_value vs new_value JSON diff

### 6.2 合规要求

| 法规 | 范围 | 措施 |
|------|------|------|
| 网络安全法 | 中国用户数据 | 数据本地化、等级保护 |
| 数据安全法 | 数据处理 | 分类分级、风险评估 |
| 个人信息保护法 | 个人信息 | 最小必要、知情同意、删除权 |
| GDPR (预留) | EU用户 | 数据可携、被遗忘权 |

### 6.3 安全事件响应

发现 -> 分级 (P0-P3) -> P0: 30分钟响应/2小时修复 -> P1: 4小时响应/24小时修复 -> P2: 24小时响应/1周修复 -> P3: 1周评估/下Sprint修复
