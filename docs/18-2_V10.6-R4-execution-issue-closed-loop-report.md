## 1. 复用与审计

- 复用 `IssueRecord` / `IssueEvent` 作为问题主记录与追加式历史。
- 复用 `GeoProject` / `ProjectWorkItem` 作为项目与来源任务。
- Skill 草稿复用 `ProjectArtifact`（`artifact_type=business_skill_draft`）。
- 权限继续使用 `NodeMembership` / `RealmService` / `GovernanceService`。
- 执行与问题入口复用 `/realm/{realm_id}/execution`。

## 2. 新增模型与迁移

- 未新增业务模型。
- 新增一次迁移 `v10p8a1b2c3d4`：
  - `issue_records` 增加版本、幂等键、影响、紧急程度、来源类型、truth scope、分类状态、验证信息。
  - `issue_events` 增加追加事件版本，并建立 `(issue_id, event_version)` 唯一约束。

## 3. 真实闭环

```text
计划任务 → 记录问题 → 规则分类建议 → 域主审核 → 处理尝试
→ 解决 → 域主验证 → Skill 草稿 → 域主确认沉淀
```

- 支持手动创建与从 `plan_task` 创建问题。
- 创建幂等键防重复；来源任务限定 `work_type=plan_task`。
- 状态机：`open → triaged → in_progress → resolved → verified`，允许 `resolved → in_progress` 和取消。
- 处理尝试追加为 `IssueEvent`，版本不重复；问题字段、状态、负责人变化均可追溯。
- 只有已验证问题可生成 Skill 草稿；未确认草稿不会激活或发布。

## 4. AI 与域主边界

- 本地规则分类明确标记 `engine=rule_based`、`truth_scope=inferred`，只作为建议。
- 自动分类不写入正式 category，必须由域主审核后确认。
- `verified` 仅限域主执行；问题验证不会自动把原任务改为 completed。
- Skill 草稿必须由域主确认后才能沉淀为能力资产。

## 5. Realm 隔离与并发

- 所有查询和修改限定 `realm_id + project_id`；跨 Realm 问题不能合并生成 Skill。
- 问题修改必须提交 `expected_version`；同一版本双会话并发只有一个成功。
- 状态更新、事件记录和版本递增在同一事务；提交失败整体回滚。
- 无权限与不存在对象统一返回 404 `resource not found`。
