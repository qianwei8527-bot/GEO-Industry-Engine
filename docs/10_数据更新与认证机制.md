# GEO-Industry-Engine 数据更新与认证机制

> 状态：架构设计 | 版本：v2.0 | 日期：2026-07-28

## 一、数据更新机制

### 1.1 更新触发方式

| 方式 | 触发条件 | 更新范围 | 延迟 |
|------|---------|---------|:--:|
| 事件驱动 | 新Event写入 | 相关Entity + 关联实体 | 实时 |
| 定时批量 | 每日凌晨2:00 | 全量GEO Score重算 | 24h |
| 手动触发 | 用户/管理员操作 | 指定Entity或行业 | 即时 |
| 配置变更 | Config/publish到active | 受影响的所有Entity | 配置生效后 |

### 1.2 事件驱动更新管道

```
Event写入 -> Event管道处理
  -> 更新Entity的相关字段
  -> 标记脏数据 (dirty flag)
  -> Decision Engine增量重算
  -> 更新缓存
  -> 推送通知(可选)
```

### 1.3 数据完整度自动检测

| 检查项 | 方式 | 触发频率 |
|--------|------|:------:|
| 必填字段 | Schema校验 | 每次写入 |
| 证据时效性 | 过期检查 | 每日 |
| 关系有效性 | 关联实体存在性 | 每次读取 |
| 行业分类准确性 | AI分类验证 | 每周 |

## 二、认证机制

### 2.1 认证生命周期

```
实体创建 (L0)
  -> 基础信息填写完成
  -> 申请L1认证
  -> AI自动审核 (数据完整度>=80%+证据>=3份)
  -> L1认证通过 (有效期2年)
  -> 积累能力证据+行业贡献
  -> 申请L2/L3/L4
  -> AI初审 + 人工复审
  -> 认证通过/驳回
  -> 定期复核 (每2年)
  -> 到期未续降级
```

### 2.2 AI审核规则

| 检查项 | 方法 | 阈值 |
|--------|------|:--:|
| 数据完整度 | 必填字段覆盖率 | >= 80% |
| 证据有效性 | 来源等级 + 时效性 | L1: >= B级3份 |
| 交叉验证 | 多源数据一致性 | >= 2源一致 |
| 风险扫描 | 负面信息检测 | 无严重负面 |

### 2.3 人工审核触发条件

- L2->L3跳级: 必须人工
- L3->L4跳级: 必须人工 + 专家委员会
- AI审核标记异常(warning)
- 用户申诉
- 随机抽检 (5%比例)

### 2.4 审核员工具

- 审核队列: 按提交时间+紧急度排序
- AI辅助: 标记可疑项+推荐判定
- 审核历史: 该实体历史认证记录
- 审核意见模板: 通过/驳回理由
- 批量操作: 同类申请批量处理

### 2.5 认证标识生成

- 数字证书: PDF (含防伪水印)
- 标识SVG: 可嵌入网页 (含L0-L4等级色)
- API验证端点: 实时验证认证有效性
- 区块链存证(未来): 认证哈希上链
