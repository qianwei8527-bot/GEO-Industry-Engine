# 恒域世界 全系统整合终极设计（整体框架）

> 上位依据：《恒域世界 V10.6：四阶段演进架构总纲》《17-2 恒域世界 V10.6 整体重构细节设计方案》
> 设计状态：整体框架稿，先冻结框架，再细化实现

## 0. 一句话理解

恒域世界 = 一套壳层 + 四个应用面 + 十个中台 + 三个底座 + 四原语可配置，全部围绕真实经营闭环。

```text
用户/客户/域主/运营/治理
        ↓
4 个应用面（统一壳层）
        ↓
6 种页面模板 + 可配置模块 + 6 种状态 + 5 级 truth scope
        ↓
10 个中台能力域
        ↓
Agent / Skills / Workflows / MCP 四原语运行层
        ↓
3 个技术底座
        ↓
外部 Provider / 数据 / 服务
```

## 1. 六层系统地图

| 层 | 内容 | 职责 |
| --- | --- | --- |
| 用户与角色层 | 域主、客户、游客、运营者、治理者 | 定义身份和权限入口 |
| 应用层 | 4 个应用面 | 提供统一壳层和一级导航 |
| 页面与组件层 | 6 种页面模板、模块、状态、truth scope | 保证页面简洁、一致、可配置 |
| 中台能力层 | 10 个中台能力域 | 统一领域模型和 API |
| 四原语运行层 | Agent、Skills、Workflows、MCP | 承载可配置执行能力 |
| 底座与外部连接层 | 3 个技术底座、外部平台 | 保证真实数据、安全和连接 |

## 2. 四个应用面

| 应用面 | 职责 | 主要入口 |
| --- | --- | --- |
| 域主工作台 | 主产品，域主完成真实经营闭环 | 今日工作、客户与定位、项目与计划、执行与问题、结果与资产、工具与连接 |
| 公共世界与客户协作端 | 客户、游客、潜在域主 | /public、/intake、/client、/market |
| 平台运营后台 | 平台运营与接口监控 | 平台总览、域管理、数据源、Feature Flag、接口监控、系统配置 |
| 治理审计台 | 权限、审批、审计、风险 | 权限策略、审批中心、审计日志、风险控制、共同治理 |

## 3. 统一壳层

四个应用面共用：

- 左侧导航：一级入口固定，Feature Flag 控制显示；
- 顶部上下文：面包屑、命令入口、环境、用户；
- 主内容区：当前工作面；
- 右侧抽屉：证据、连接、权限、审批；
- 底部状态条：数据连接、truth scope、版本。

页面固定使用六种模板：

| 模板 | 场景 |
| --- | --- |
| 工作页面 | 今日工作、单步骤执行、项目经营 |
| 列表页面 | 项目、任务、问题、审批、能力包 |
| 详情/展示页面 | 企业、品牌、产品、域、案例、能力包 |
| 配置页面 | 工作流、Agent、连接、Feature Flag |
| 管理页面 | 平台后台、治理、审计、交易运营 |
| 探索画布 | 行业地图、关系图谱、政策影响、情景推演 |

## 4. 四原语原则

| 原语 | 归属 | 可配置内容 | 运行后必须记录 |
| --- | --- | --- | --- |
| Agent | 域主或平台 | 角色、目标、工具、模型、预算、权限 | 输入、输出、版本、引用、成本 |
| Skills | 域主 | 技能包、版本、来源、适用条件、授权 | 调用、失败、复盘、Skill 候选 |
| Workflows | 域主 | 步骤、条件、节点、人工确认点 | 每次运行、跳过、失败、人工确认 |
| MCP | 平台与域主 | 连接、工具、资源、权限、密钥策略 | 连接状态、调用、审计、风险 |

四原语统一闭环：

```text
目录 → 配置 → 授权 → 运行 → 记录 → 复盘 → 资产
```

四原语不是业务真相源，只负责执行；所有事实仍以 Evidence、Outcome 和真实项目记录为准。

## 5. 可配置原则

所有可配置内容都遵循：版本化、可审计、可回滚。

| 配置层 | 内容 | 由谁配置 |
| --- | --- | --- |
| 页面配置 | 模块开关、排序、默认状态 | 域主 |
| 原语配置 | Agent 参数、Skill 版本、Workflow 步骤、MCP 连接 | 域主/平台 |
| 中台配置 | 域权、评分、证据规则、连接策略 | 平台/治理 |
| 平台配置 | Feature Flag、数据源、接口监控 | 平台运营 |
| 系统配置 | 模型、额度、安全、备份 | 平台运维 |

## 7. 三个技术底座

| 底座 | 职责 |
| --- | --- |
| 数据、事件与平台底座 | PostgreSQL、对象存储、搜索、向量、知识图谱、缓存、Event Backbone、Queue、Scheduler、Notification、Snapshot、备份恢复 |
| Agent 与工作流运行底座 | Agent Runtime、Workflow Runtime、Tool Execution、Memory、Citation、Sandbox、Budget、Human Approval、幂等、重试、可观测性 |
| 外部连接与安全底座 | MCP、Adapter、API、Webhook、Callback、Credential、Secret、Rate Limit、SSRF 防护、数据出境策略、连接审计 |

## 8. 权限、真实性与审计

1. `node_memberships` 是操作权限真相源，前端不自行判断身份。
2. AI 提取默认 draft、observed、inferred；unknown 不得补造。
3. simulation 不得写入生产关系。
4. 外部动作按低、中、高三级授权，禁止动作永不自动执行。
5. 不建立第二套 Realm、Evidence、Demand、Connection、Outcome 或权限体系。
6. 未批准不新增数据库模型和迁移。

## 9. 统一数据流

```text
用户在应用面操作
→ Feature Flag 检查
→ 权限检查
→ 页面模板渲染
→ 模块调用统一 API
→ 中台能力域处理
→ 四原语运行
→ 底座持久化与审计
→ 外部 Provider/数据/服务
```

所有写操作进入审计；高风险操作进入人工确认。

## 10. 落地顺序

1. 设计令牌与统一 Shell；
2. 公共资料提交；
3. 域主工作台；
4. 平台运营后台；
5. 治理审计台；
6. 四原语可配置中心；
7. 数据底座与外部连接接入；
8. 能力市场与行业态势（后续阶段）。

## 11. 验收标准

- 四个应用面都有真实壳层或冻结协议；
- 页面由可配置模块组成；
- 四原语可配置、可运行、可审计；
- 所有数据源状态可见，缺失接口保留真实空状态；
- truth scope 五级正确；
- 无第二套路由、权限和数据模型；
- TypeScript、lint、测试和生产构建通过。
