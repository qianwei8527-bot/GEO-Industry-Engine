## 二、数据库性能

### 2.1 索引策略

| 表 | 索引 | 用途 |
|----|------|------|
| entity | (tenant_id, entity_type) | 多租户过滤 |
| entity | (name) GIN trigram | 模糊搜索 |
| company | (industry_id, geo_score DESC) | 行业排行榜 |
| certification | (entity_id, level) | 认证查询 |
| event | (entity_id, occurred_at DESC) | 事件时间轴 |
| relationship | (source_id, rel_type) | 关系图查询 |
| evidence | (entity_id, source_level) | 证据质量过滤 |

### 2.2 查询优化

- N+1 问题: 使用 selectinload/joinedload 预加载
- 大数据集: 分页 + keyset pagination
- 聚合查询: 物化视图 (排行榜、行业统计)
- 慢查询监控: SQLAlchemy event listener

### 2.3 连接池

| 参数 | 值 |
|------|----|
| pool_size | 20 |
| max_overflow | 10 |
| pool_recycle | 3600s |
| pool_pre_ping | true |

## 三、API性能

### 3.1 响应优化

- 列表接口默认分页: page_size=20
- 大报告异步生成: POST /reports -> 202 Accepted -> 轮询
- 文件导出: 后台任务 + 下载链接

### 3.2 缓存

- Redis 缓存: GEO Score / 行业指数 / 排行榜
- HTTP Cache-Control: 静态资源 1年
- CDN: 前端构建产物 (JS/CSS/图片)

---

## 四、前端性能

### 4.1 加载优化

- Next.js SSG: 首页/产业导航 (ISR 1h)
- 代码分割: route-based + lazy load
- 图片优化: next/image + WebP
- 字体: next/font + subset

### 4.2 运行时优化

- React.memo 避免不必要重渲染
- 虚拟列表 (大数据集表格/列表)
- Debounce 搜索输入 (300ms)
- Web Worker 大文件处理
