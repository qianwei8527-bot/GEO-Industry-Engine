# GEO-Industry-Engine 发布流程 v2

> 每次 Sprint 结束和版本发布必须遵循本流程。

---

## 一、发布类型

### Sprint发布（2周一次）
```
结束前2天：冻结代码，仅bug修复
结束前1天：全量回归测试
结束日：发布评审，CTO批准
发布后1天：监控运行状态
```

### 版本发布（里程碑）
```
v{major}.{minor}.{patch}
v1.0.0 - MVP发布
v1.x.0 - 重大功能发布
v1.0.x - Bug修复发布
```

### 紧急发布
```
1. 创建 hotfix 分支
2. 修复后经 CTO 紧急审批
3. 直接发布，事后补测试和文档
```

---

## 二、发布检查表

### 代码
[ ] 所有代码已合并到主分支
[ ] 无未解决的 merge conflict
[ ] 符合编码规范
[ ] 无遗留 TODO/FIXME

### 测试
[ ] 所有单元测试通过
[ ] 所有 API 测试通过
[ ] 回归测试通过
[ ] 覆盖率 >= 80%

### 文档
[ ] 新增功能文档已更新
[ ] API 文档已同步
[ ] REFERENCES.md 已更新

### 部署
[ ] Docker构建成功
[ ] 迁移脚本已验证
[ ] 环境变量配置正确
[ ] 健康检查正常

---

## 三、发布流程

```
Step 1: 发布准备
  确认所有任务完成 -> 全量测试 -> 更新版本号

Step 2: 发布评审
  CTO确认条件 -> 各Agent确认 -> 批准发布

Step 3: 发布执行
  git tag -> Docker构建 -> 部署 -> 健康检查

Step 4: 发布验证
  服务正常 -> 冒烟测试 -> 数据完整

Step 5: 发布记录
  版本+变更 -> changelog -> 通知
```

---

## 四、回滚

| 场景 | 方式 | 恢复时间 |
|------|------|---------|
| 代码问题 | git revert + 重部署 | 30分钟 |
| 数据库问题 | Alembic downgrade | 30分钟 |
| 配置问题 | 恢复环境变量 | 15分钟 |
| 数据问题 | 从备份恢复 | 2小时 |

任何回滚后必须创建 bug 修复任务追踪到关闭。
