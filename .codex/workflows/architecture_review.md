# GEO-Industry-Engine 架构变更审核流程

> 任何涉及架构变更的开发行为，必须遵循本流程。

---

## 一、触发条件

以下变更必须走架构审核流程：

| 变更类型 | 示例 | 审核级别 |
|---------|------|---------|
| 新增数据表 | 新增 entities, capabilities 等表 | CTO Agent |
| 修改数据模型 | 修改 Entity 基类字段 | CTO Agent |
| 新增 API 分类 | 新增 /api/v1/context/ | CTO Agent |
| 修改 API 规范 | 修改统一响应格式 | CTO Agent |
| 新增技术栈 | 引入新的数据库、框架 | CTO Agent |
| 修改项目结构 | 新增顶级目录 | CTO Agent |
| 新增前端页面 | 新增核心页面 | CTO Agent |
| 新增 Agent | 新增业务 Agent | CTO Agent |

---

## 二、审核流程

```
Step 1: 发起变更请求
  - 提出变更原因和目标
  - 说明变更影响范围
  - 指定受影响文档

Step 2: CTO Agent 审查
  - 检查与冻结架构的一致性
  - 评估影响范围
  - 给出审查结论

Step 3: 影响 Agent 评估
  - 产品经理 Agent：验证用户价值
  - 后端 Agent：评估实现方案
  - 前端 Agent：评估前端影响
  - 测试 Agent：评估测试方案

Step 4: CTO 最终批准
  - 通过：可开始开发
  - 有条件通过：需满足条件后开发
  - 驳回：返回修改或放弃

Step 5: 文档同步
  - 文档 Agent 更新相关文档
  - 更新 .codex/REFERENCES.md
  - 记录架构变更日志

Step 6: 执行与验收
  - 开发 Agent 按方案执行
  - 测试 Agent 完成验收
  - CTO Agent 确认关闭
```

---

## 三、审核标准

### 通过条件
- 与 35_CTO架构冻结.md 完全一致
- 属于五大产品系统之一
- 不影响已有数据结构和 API
- 有清晰的测试方案

### 驳回条件
- 违反冻结架构中的禁止事项
- 不符合产品宪章定位
- 破坏已有模块兼容性
- 没有明确用户价值

---

## 四、紧急变更通道

以下场景可走紧急通道（24小时内完成审核）：

1. 安全漏洞修复
2. 生产环境故障修复
3. 数据丢失风险修复

紧急变更仍需要事后补充文档和审查记录。
