## 八、思维框架（如何思考，不是做什么）



### 组件复用优先
在新建任何页面/组件/工具函数之前：
1. 搜索已有组件: rg --files frontend/src/ | grep -i <关键词>
2. 检查 lib/api.ts 是否已有对应接口封装
3. 检查已有页面是否有可复用的布局/卡片/表单模式

> 新建页面 = 最后手段。优先：已有页面加区块 > 已有组件参数化 > 抽取公共组件 > 新建。

**常见可复用场景：**
- 新页面布局 → Header+Footer+五大系统导航已存在
- 数据展示卡片 → 检查已有评分卡/统计卡/列表卡
- 表单输入 → 检查已有登录/注册/检测页面的表单结构
- API调用 → api.ts 中是否已有对应端点封装

### 3秒法则
用户打开页面，3秒内：
- 知道自己在哪个系统（检测/认证/导航/资产/交易）
- 知道这个页面能做什么
- 知道下一步操作在哪

如果3秒内做不到，页面设计有问题。

### 状态优先
设计页面时，先设计三个状态，再设计正常态：
1. Loading — 数据到了之前用户看到什么？
2. Empty — 数据为空时用户看到什么？
3. Error — 出错时用户看到什么？

正常态是第四个状态。四个状态都覆盖才算完成。

### Mobile-First
- 先设计375px宽度的布局，再扩展到桌面
- 导航在手机上怎么展示？卡片在手机上怎么排列？
- 触摸目标至少44x44px

## 九、质量自检（输出前必须回答）

1. **三态覆盖**: loading/empty/error 三个状态都实现了吗？
2. **数据来源**: 所有数据都从API来吗？有没有硬编码的？
3. **API封装**: 是否使用了 lib/api.ts 而不是裸 fetch？
4. **导航清晰**: 切换到这个页面后，Header/Breadcrumb显示正确吗？
5. **移动端**: 在375px宽度下还能用吗？

## 十、领域锚点（永不可忘）

### 五大系统入口结构
```
导航栏
├── 检测中心 (第1项, 蓝色)
├── 认证中心 (第2项, 金色)
├── 产业导航 (第3项, 绿色)
├── 数据资产中心 (第4项, 紫色)
└── 交易市场 (第5项, 橙色)
首页 = Hero + 5系统卡片 + 搜索入口
```

### 页面规范
- 检测中心: 搜索→结果，两步流
- 产业导航: 地图+数据，双栏布局
- 数据资产: 列表+统计，表格风格
- 认证中心: 表单+状态，流程风格
- 交易市场: 商品+搜索，电商风格

## 十一、进阶反模式

| 反模式 | 为什么容易犯 | 怎么自我检测 | 纠正 |
|--------|------------|------------|------|
| 裸fetch | 方便快速 | 代码里有没有/api/v1/之外的fetch？ | 改用api.ts |
| 无三态 | 只做了正常态 | 断网或清空数据库后页面白屏吗？ | 加三态 |
| 超大组件 | 一个文件写所有 | 组件超过200行了吗？ | 拆分 |
| 硬编码文案 | 赶进度 | 页面文案能改吗？是不是写死在JSX里？ | 提到配置 |
