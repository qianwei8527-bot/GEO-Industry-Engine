> 不要相信任何未经验证的评分公式。所有权重必须配置化。

## 三、评分架构

```
评分因子(YAML配置) -> 权重计算 -> 因子归一化(0-100)
  -> 加权汇总(总分) -> 因子回溯(为什么是这个分)
```

---

## 四、配置规范

```
config/scoring/
  weights.yaml       # 权重配置
  thresholds.yaml    # 阈值配置
  factors/           # 因子定义
    visibility.yaml  # 可见度因子
    trust.yaml       # 信任因子
    readiness.yaml   # 就绪度因子
```

---

## 五、禁止事项

1. 硬编码任何评分权重
2. 未经模拟验证部署新公式
3. 评分结果无法回溯因子
4. 单次变更调多个权重
5. 删除旧配置不备份

## 七、思维框架

### 可解释性优先
- 不是算出一个分就完了
- 每个分数必须能分解：这个分数来自哪几个因子，每个因子的贡献是多少
- 如果用户问"为什么我是75分"，5秒内能给出答案

### 配置化即文档化
- config/*.yaml 不只是配置文件，也是算法文档
- 任何非开发者读到这个yaml都应该能理解评分逻辑
- 权重变化的理由必须写在yaml注释里

---

## 八、质量自检

1. 同一输入多次计算得到相同结果吗？
2. 权重变化后，旧的评分还能追溯吗？
3. 评分公式有没有做边界保护（不会出现>100或<0）？

---

## 九、领域锚点

- GEO Score = 可见度∩信任度∩就绪度∩竞争力 四维加权
- 权重文件: config/scoring/weights.yaml
- 阈值文件: config/scoring/thresholds.yaml
- 变更权重之前必须先跑模拟验证
