# 模糊指令处理规则

> 规则编号：R-002 · 优先级：P0 · 覆盖默认行为
> 触发条件：用户指令过于抽象或模糊，存在多种解释可能

---

## 一、触发条件

当用户指令符合以下任一特征时，本规则生效：

| 特征 | 示例 |
|------|------|
| 没有具体操作对象 | "帮我优化一下" |
| 存在多种解释可能 | "把这个改一下"（改什么？怎么改？） |
| 缺乏验收标准 | "让页面更好看"（什么叫好看？） |
| 跨多个流程/系统 | "帮我做一下用户系统"（注册？登录？权限？） |
| "先看看"/"想想"类 | 可能是咨询也可能是开发 |

**本规则PRIORITY高于AGENTS.md默认路由规则。触发本规则时，不直接执行。**

---

## 二、处理流程

```
Step 1: 歧义检测
  - 这句话有几个可能的理解？
  - 如果直接执行，做出来的东西可能和用户预期差多远？
  - 如果存在2个以上的解释 → 触发本规则

Step 2: 拆解分析
  输出 ## 需求分析
  A. 你的原话：{原文引用}
  B. 可能的理解（列出2-3个）：
     理解1：{具体是什么}
     理解2：{具体是什么}
  C. 我的建议理解：{推荐的}
  D. 如果按建议理解执行，产出将是：{具体产出}

Step 3: 等待确认
  发回给用户确认。
  用户说"执行"/"按这个来"/"对"后，才进入正常流程。
  用户说"不对"后，继续讨论直到达成共识。
```

---

## 三、模糊度判断

| 评分 | 表现 | 处理 |
|------|------|------|
| L0 明确 | "帮我把检测页面的API从fetch改成api.ts封装" | 直接执行 |
| L1 略模糊 | "优化检测页面性能" | 分析后执行，告知假设 |
| L2 模糊 | "帮我做一下产业导航" | 触发本规则，先分析后确认 |
| L3 很模糊 | "这个项目接下来怎么做" | 触发本规则，先分析后确认 |

---

## 四、注意

1. 模糊不是错误。用户在用高层语言表达，AI需要翻译成可执行语言
2. 宁可多一步确认，不要做出不符合预期的东西
3. L0-L1可以在分析后直接执行并告知假设
4. L2-L3必须先分析后确认
