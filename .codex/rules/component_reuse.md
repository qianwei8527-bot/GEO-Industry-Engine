# 代码复用检查规则

> 规则编号：R-003 · 优先级：P0
> 触发：任何 Agent 准备创建新文件、新模块、新工具函数时
> 原则：复用优先于新建。先证明不可复用，再允许创建。

---

## 一、复用优先级

```
第1优先: 直接使用已有模块/函数/组件
第2优先: 参数化扩展现有模块（不改已有逻辑）
第3优先: 从已有模块抽取公共逻辑
最后手段: 新建文件
```

---

## 二、复用检查流程（三步扫描）

### Step 1: 模式搜索
新建代码前，用 rg 扫描代码库：
```
# 搜索相似文件名
rg --files | grep -i <功能关键词>

# 搜索相似函数签名
rg "def <函数名模式>" backend/app/

# 搜索相似组件
rg "export.*function.*<组件名>" frontend/src/

# 搜索相似 API 路径
rg "@router\.(get|post|put|delete).*<路径模式>" backend/app/api/
```

### Step 2: 映射检查
查 REFERENCES.md，确认是否有已注册的同类型模块。

### Step 3: 输出复用报告
格式见 .codex/protocol.md 的复用检查段。

---

## 三、允许新建的条件

新建代码前必须满足以下至少一条：

| 条件 | 示例 |
|------|------|
| 已有模块功能不重叠 | 新增的是完全不同领域的数据模型 |
| 参数化会导致破坏性变更 | 已有API大量调用，加参数会影响全部调用方 |
| 已有模块职责完全不同 | 新增的不是"另一个CRUD"，而是"Context Engine"这类新能力 |
| 代码中确实不存在相同模式的实现 | rg 三次搜索均无匹配 |

**不满足任何一条 → 先复用，后新建。**

---

## 四、违规检测

| 信号 | 含义 | 处理 |
|------|------|------|
| 新建文件但 REFERENCES.md 中已有同类模块 | 重复造轮子 | 驳回 |
| 新函数名与已有关键词高度相似 | 疑似重复 | 要求先查已有实现 |
| 同一天内新建3个以上同类型文件 | 批量重复 | 暂停审查 |
