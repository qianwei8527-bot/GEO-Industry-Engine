# 恒域世界（GEO-Industry-Engine）

**域主经营行业域、沉淀可信资产并复制产业能力的世界操作系统。**

> `GEO-Industry-Engine` 是当前仓库名；“恒域世界”是上位产品架构，“恒域世界-GEO”是首个行业世界与第一阶段验证场。

恒域世界不是单一 GEO 检测工具、通用 AI 办公助手或普通交易平台。它以“域”为基本经营单元，让真实的人与组织在统一工作台中完成资料收集、分析、计划、执行、问题处理、证据验证、成果复盘与能力沉淀，并在授权、确权和可信治理边界内复用或交易产业能力。

---

## 当前阶段

项目已进入 **V10.6 正式冻结版的第一阶段：单域真实经营闭环**。

当前只聚焦：

- 一个垂直赛道；
- 一个真实域主；
- 一个核心产品；
- 一类目标客户；
- 一个主要转化目标。

第一阶段闭环：

```text
资料提交
  → AI结构化分析
  → 域主确认
  → 建立项目与执行计划
  → 任务执行与问题收集
  → Evidence / Outcome
  → 复盘纠偏
  → Skill / Workflow / UI Preset候选
  → 验证复用
  → 域能力包
```

在第一个真实闭环和第二次有效复用完成前，不横向扩建新系统，不重做核心架构，不提前实现后续阶段页面。

## 统一产品形态

恒域世界采用：

> **WorkBuddy 式 AI 工作台壳 + 当前域语境 + 对话/任务/工作面 + 本地源码主权 + 外部工具适配 + 自动资产化 + 域能力复用与交易。**

WorkBuddy 只作为自然语言工作流与 Projects、Experts、Skills、Connectors 组织方式的参考。恒域世界必须保留自己的 Realm、Evidence、Claim、Outcome、权属、审计、可信状态和能力资产化体系，不复制其他产品的品牌或视觉。

### 四个应用面

| 应用面 | 核心职责 | 当前状态 |
|---|---|---|
| 域主工作台 | 域主经营、计划、执行、确认、复盘和资产沉淀 | `/realm/{realm_id}/*`，R1 已接入统一壳层 |
| 公共世界与客户协作端 | 公共展示、资料提交、客户协作和能力市场 | `/public/*`、`/intake/*`、`/client/*`、`/market/*`；当前先落地 `/intake/{secure_token}` |
| 平台运营后台 | 政策、经营支持、生态运营和服务协调 | 协议冻结，暂不创建空壳页面 |
| 治理审计台 | 权限、证据、风险、申诉、审计和平台治理 | 协议冻结，暂不创建空壳页面 |

四个应用面共用一套核心 `AppShell`，通过配置切换导航范围、权限与内容区，不建立第二套壳层、路由、权限或数据体系。

## V10.6-R1 已落地

### 统一 Shell

- `AppShell` 只有一套核心实现；
- owner 与 public 通过配置复用；
- operations 与 governance 只冻结协议，不建立空页面；
- 域主工作台继续使用 `/realm/{realm_id}/explore`。

### 公共资料提交

- 域主可生成有有效期、可撤销、绑定 Realm 的客户资料提交入口；
- 公共入口使用 `/intake/{secure_token}`，不接受调用方自行传入 `realm_id`；
- 支持草稿、正式提交、去重、限流、文件校验和 URL SSRF 校验；
- 所有关键行为进入 `AuditLog`；
- 客户提交的内容先进入等待域主确认状态；
- 未配置外部 AI Key 时展示真实阻塞，不生成模拟分析。

### 状态与可信表达

- 复用统一的六种模块状态；
- 统一使用五级 `TruthBadge`；
- 补齐 `DataSourceBadge`、`StatusStrip`、`ApprovalItem`；
- 空状态、失败、阻塞、无权限和无 AI Provider 必须真实展示。

- 在标准环境或 CI 补跑 `ruff`；`py_compile` 与测试不能替代静态检查。

## 可信与治理边界

1. AI 提取默认只能进入 `draft`、`observed` 或 `inferred`，不得自动生成 `verified`。
2. 域主可以确认资料与经营事实，但不能自行制造平台级可信认证。
3. 任务 `completed` 不自动提高信誉；Outcome 不自动制造 Evidence。
4. AI 与工具运行必须保留输入、输出、Provider、模型/工具版本、配置哈希、引用、成本、权限范围和执行状态。
5. 无 Key、网络失败、权限不足、外部工具失败与问题 Occurrence 必须真实保留，不得静默伪造成功结果。
6. `entities.id` 是统一 Realm ID 链；`node_memberships` 是控制权与成员权限的唯一真相源，其他 owner 字段只能作为缓存。
7. 模拟、演示和测试数据必须标记来源与等级，不得在对外界面或报告中冒充真实数据。

## 域能力资产化

域主在真实项目中形成的有效经验，可以沉淀为：

- SOP；
- Workflow；
- UI Preset；
- Agent / Skill；
- 工具模板；
- 规则与指标；
- 案例与证据结构。

经过测试、证据绑定、版本管理、权属确认和许可配置后，可形成“域能力包”，供复用、授权或进入域能力市场。

域能力包不得包含客户原始数据、私密文件、账号凭证、密钥、未脱敏个人信息或未经授权的第三方内容。

## 外部工具与源码主权

- Codex、OpenClaw、第三方 AI、发布平台和行业工具统一通过 Adapter、MCP、API 或 Webhook 接入；
- 外部工具是执行能力层，不替代恒域世界的 Realm、权限、证据、审计与资产化核心；
- AI 对界面、工具和流程的修改必须落入域主可控制的本地工作区；
- 源码修改应保留 diff、测试结果和提交记录；
- 外部动作按照风险等级授权，不得将“一次授权”扩大为无限权限。

## 开发原则

1. **真实闭环优先**：任何开发都必须说明服务哪个真实域主任务、处于闭环哪一步、产生什么可验证结果。
2. **复用优先**：先复用现有 Shell、路由、权限、实体、证据、状态和组件，证明无法复用后才允许新建。
3. **简洁优先**：优先采用“上传/粘贴资料 → AI分析 → 域主确认”，不得把复杂配置和长表单交给域主。
4. **配置化与可控**：指令、流程、模板、Provider、规则和界面预设应可配置、可替换、可版本化。
5. **不制造事实**：AI 可以提取、归纳、推断和提出建议，但必须标明来源与可信等级。
6. **范围匹配验证**：修改后运行与范围匹配的测试；未运行不得声称完成。
7. **不提前铺开**：后续应用面和阶段只冻结协议或 Feature Flag，不创建没有真实任务的页面、模型和流程。
8. **不自动发布**：未经用户明确授权，不部署、不提交、不推送，也不触碰无关修改。

## 当前判断

恒域世界已经从“GEO 行业世界功能系统设计”进入“真实域主经营闭环实施”。当前工作的衡量标准不再是增加页面、模型或文档数量，而是：

> 一个真实域主能否通过统一工作台，让客户安全提交资料，完成真实分析与确认，建立项目和计划，持续执行并收集问题，形成可验证结果，最终沉淀出能够再次复用的域能力。

> **让每个域主在真实经营中找到自己的位置，并把有效经验沉淀为可验证、可复制、可授权的产业能力。**
